Оркеструй батч закрытия тест-гепов одной группы (несколько `[test]`-issue одного пакета) ИЛИ в discovery-режиме (сам находит все открытые test-gap issue): один worktree → per-gap **дискриминирующий** тест (мутационно доказанный, НЕ green-pin) → по коммиту на геп прямо в `master`. **Дифф только из тестов — инфраструктура:** без ветки задачи, PR и changeset (корневой CLAUDE.md, «Infrastructure tasks go straight to `master` — no PR, no changeset»).

Входные данные:
$ARGUMENTS

Формат аргументов:

- **Явный список** `[test]`-issue одной группы (`#1178 #1181 #1179`) — обычно одна тема (reentrancy / start / stress-hygiene) одного пакета.
- **Без аргументов (или `all`) → discovery-режим:** сам находит все открытые test-gap issue (Шаг 0.0), группирует по пакету, подтверждает скоуп ПЕРЕД правкой. Сузить: `all <фильтр>` — напр. `all core`, `all priority:medium`.

Этот скилл — **ОРКЕСТРАТОР**. Изоляцию ГРУППЫ (worktree вне репозитория, `EnterWorktree`, `pnpm install` без dist, возобновление, worktree-жизненный-цикл) и точечную валидацию он **НЕ дублирует — берёт как `/bugfix-batch` Шаги 1 и 3**; доставка другая: дифф из одних тестов идёт прямо в `master`, без ветки задачи, PR и changeset. Здесь — только тест-геп-специфика: классификация гепа + **дисциплина дискриминации** + маршрут «тест vs всплывший баг». Механику property берёт из `/audit-pbt` / `/pbt-scenarios`, stress — из `/stress-scenarios` / `/audit-stress`, метод мутации — из `/mutation-score`, всплывший баг — в `/bugfix`.

## Шаг 0 — Discovery (если нет списка) + fetch + классификация КАЖДОГО гепа

**0.0 — Discovery (только без явного списка).** `gh issue list --state open --label "area: tests" --json number,title,labels` → отбери test-gap по заголовку (`[test]` / `[<pkg>][test]`, «untested»/«unpinned»/«coverage gap»/«never exercised»/«property gap»/«stress gap»/«vacuous»/«survives mutation»/«not asserted»). **ОТСЕЙ не-test с меткой `area: tests`** (чистая tooling/CI-задача без нового теста). Сгруппируй по пакету/области, выведи таблицу `#N · пакет · приоритет · класс гепа`, **подтверди скоуп у пользователя ПЕРЕД правкой** (набор бывает большой — юзер может срезать до `all core` или до темы). Один пакет с 10+ гепами разбей на тематические под-группы (reentrancy / start / stress) — одна под-группа = одна ветка/PR.

`gh issue view <N>` на каждый. Классифицируй КАЖДЫЙ пункт — класс определяет метод:

- **MISSING-coverage** (непокрытая ячейка/ветка/путь): новый тест, ПИННящий КОРРЕКТНОЕ поведение существующего кода.
- **TEST-INTEGRITY** (существующий тест зелен на СЛОМАННОМ коде — green-pin, self-catching try/catch, sleeping/`await sleep` assertion, tautology на ложной посылке, title≠body, duplicate describe): **ПОЧИНИ лживый тест**, чтобы он дискриминировал. Это НЕ «добавить покрытие» — это ремонт теста, который уже «зелёный», но ничего не ловит (#1189/#1243/#1209/#1183 класс).
- **PROPERTY-gap** (инвариант без генеративного локка): property-тест — метод из `/audit-pbt` / `/pbt-scenarios`; сверь/допиши строку в `INVARIANTS.md`.
- **STRESS-gap** (concurrency / memory / throughput без нагрузочного локка): stress-тест — метод из `/stress-scenarios` / `/audit-stress`; **порог обязан иметь доказанную дискриминирующую силу** (healthy < threshold < leak, ≥3× margin; см. корневой CLAUDE.md про heap-thresholds — round-MB guess = theatre).
- **BUG-revealing** (геп-филл тест ПАДАЕТ на текущем коде): это **БАГ**, не тест-геп. Эскалируй в `/bugfix` (отдельная ветка + changeset на src-фикс). НЕ подгоняй тест под green — issue остаётся про баг, тест-пин коммить вместе с фиксом.

## Шаг 1 — Один worktree на группу — изоляция **как `/bugfix-batch` Шаг 1**, без ветки задачи

Worktree вне репозитория, отделённый от `master` (`git worktree add --detach <каталог вне репо> master`) → `EnterWorktree path:` → **`pnpm install --frozen-lockfile` в worktree ПЕРЕД любой пробой/прогоном** (свежий worktree не делит `node_modules`; dist НЕ собирай). Worktree нужен для проб: мутация правит `src`, а в общем основном чекауте это задело бы чужую работу. Коммиты копятся на detached HEAD; в `master` их переносит владелец (`git merge --ff-only <sha>` в основном чекауте — рецепт в корневом CLAUDE.md, правило про worktree) или `git push origin HEAD:master` по явной просьбе. Возобновление: `pwd` + `git log --oneline master..HEAD` перед пере-созданием. Команды и resume-ловушки — в `/bugfix-batch` Шаг 1, не дублирую.

## Шаг 2 — Per-gap цикл (ЯДРО этого скила)

Для КАЖДОГО гепа по очереди:

1. **Заземли на РЕАЛЬНОМ src+тесте, НЕ на issue-черновике.** Issue — гипотеза на момент заведения: описанная непокрытая ячейка могла быть покрыта позже, «vacuous» тест — уже починен, «survives mutation» мутант — уже killed, счётчик/строка — уплыть. Прочитай ЦЕЛЕВОЙ тест-файл + целевой src ПЕРЕД правкой; если геп уже закрыт — триаж-non-gap (Гейты). (Симметрично doc-batch verify-against-source.)
2. **Напиши/почини тест — и ДОКАЖИ дискриминацию МУТАЦИОННО (несущее правило).** Тест, который не краснеет на сломанном поведении, — мусор: это РОВНО анти-паттерн, что эти issue репортят. Для КАЖДОГО добавленного/починенного теста: **сломай ТОЧНУЮ src-ветку/поведение, что он целит** (или удали фикс/инвертируй условие) → тест ОБЯЗАН покраснеть; верни → зелёный. **Не покраснела → сперва подозревай САЙТ, не тест** (для функц. теста, в отличие от property, где это обычно дырявый генератор): guard/cancel-поведение имеет sync/async близнецы (`runFrom` ↔ `resumeFrom` в `transition/guardPhase.ts`) и канонизирующие стоки (`settleLeavePromises` перезаворачивает любой abort-reason → `TRANSITION_CANCELLED`) — мутация не того близнеца или ВЫШЕ канонизатора остаётся зелёной, хоть поведение сломано. Ре-таргетируй на путь, который ИМЕННО ЭТОТ тест исполняет, до вывода «тест недискриминирующий».
   - **Нет существующей ветки (negative/acceptance-пин)?** Пин «core НЕ гейтит X» / «core ПРИНИМАЕТ X» / «CRUD проходит в окне» не имеет ветки для мутации — в этом и суть гепа (напр. #1204 «STARTING не имеет CRUD-гейта», #1189 «param-value validation opt-in»). Не объявляй его недоказуемым: докажи дискриминацию, **СИМУЛИРОВав регресс, от которого тест сторожит** — временно ДОБАВЬ гейт/валидацию/ban (напр. расширь `isTransitioning()` спаном окна, добавь `if (isTransitioning()) return` в CRUD, коерсируй значения параметров) → тест ОБЯЗАН покраснеть → restore. Это и есть «сломать поведение, что тест целит» для случая отсутствия-ветки.
   - **Вердикт — по падению ТЕСТА, эмпирически** (`feedback_mutation_audit_empirical`): не чтением, не exit-кодом Stryker, не «оно должно ловить». Green-до-мутации тест — недискриминирующий пин, находка сама по себе (в TEST-INTEGRITY именно это и чинишь).
   - **Тесты ОХОТЯТСЯ за багами, не пиннят** (`feedback_tests_hunt_bugs_not_pin`): пиши как скептичную пробу на реальном src. Геп-филл ПАДАЕТ на текущем коде → это БАГ (Шаг 0 BUG-revealing → эскалация в `/bugfix`), а не «сделать зелёным».
   - **Через ПУБЛИЧНЫЙ API** (`feedback_kill_mutants_via_public_api`, `/whitebox-audit`): закрывай геп через публичную поверхность, не белым ящиком по внутренним символам — white-box-тест прячет мёртвый/недостижимый код от coverage. Внутренний доступ — только с явным обоснованием (memory/perf-инвариант).
   - **TEST-INTEGRITY-ремонт:** сними маскирующий try/catch (глотает throw), убери sleeping/`allSettled`-глушилку, разверни tautology, приведи title к ФАКТИЧЕСКОМУ assert. Докажи: ПОЧИНЕННЫЙ краснеет на мутации, СТАРЫЙ — нет (в этом весь ремонт).
   - **Timing-правка ядра** → прогони `test:properties` + `test:stress` затронутого пакета (`feedback_sweep_properties_stress_on_timing_change`).
   - **Coverage:** 100% пакета; **per-FILE** для phantom-порога адаптеров (svelte/angular — aggregate `Tests N passed` НЕ доказывает покрытие ТВОЕГО файла; смотри строку файла в coverage-таблице).
3. **Отдельный коммит на КАЖДЫЙ геп:** `#<N>` в заголовке и `Closes #<N>` в теле (`/commit-msg`) — issue закроется, когда коммит попадёт в `master`. **Changeset не нужен** ни на тесты, ни на правку только комментариев в `src/`: стухший коммент рядом с тестируемым кодом (doc-item аудита) идёт тем же путём, своим коммитом. Коммить `--no-verify` + точечный `pnpm -F <pkg> test -- --run` (+ `test:properties`/`test:stress` по классу) **+ точечный `eslint`/`prettier` по изменённым тест-файлам** ПЕРЕД коммитом (per-package; полный граф прогоняет pre-push). **Lint — не опционален:** pre-commit `--no-verify`'нут, так что без локального `eslint` ошибка всплывёт только на pre-push. Снят и `commit-msg`, а сообщения не читает ни pre-push, ни CI: проверь его тем же вызовом (`/commit-msg`, «Проверка»). **Захват sync-throw** из promise-возвращающего метода (reentrant-ban / cached-rejection / start-after-dispose) — через `captureSyncThrow(fn)` / `expect(() => …).not.toThrow()`, **НЕ** `try { void call() } catch` (= `sonarjs/no-try-promise`, красный CI). **Всплыл баг на Шаге 2** → src-фикс отдельным коммитом **+ changeset** (via `/bugfix`), RED-тест-пин — своим коммитом; issue тогда про баг, `Closes` вешается на баг-фикс. Гранулярность и `git add <файл>`-дисциплина — как `/bugfix-batch` Шаг 2.

## Шаг 3 — Финал на группу — **как `/bugfix-batch` Шаг 3**

Точечная валидация объединённого набора пакетов (`type-check`/`lint`/`test -- --run` + `test:properties`/`test:stress`; подтверждай `Tests N passed`, не только `exit 0`). Доставка — перенос коммитов в `master` (Шаг 1); push — только по явной просьбе и без `--no-verify`: pre-push прогоняет весь граф, и до `master` это единственная полная проверка. Wiki обычно НЕ при чём (тест-геп доки не трогает — если тронул поведенческую доку, отдельный wiki-коммит как `/bugfix-batch` 3.2). Полный `pnpm build` сам не гоняй. Детали валидации — в `/bugfix-batch` Шаг 3.1.

## Гейты

- **НЕ push и НЕ issue-comment без явной просьбы** — готовь, показывай, жди «go». Локальные per-gap коммиты — воркфлоу, не гейт.
- **НЕ помечай геп закрытым, пока тест не ДОКАЗАН дискриминирующим** (мутация красит эмпирически). Зелёный-но-недискриминирующий = геп НЕ закрыт (иначе воспроизведёшь ровно тот дефект, что issue репортит).
- **BUG-revealing геп ≠ тест-геп.** Геп-филл падает на текущем коде → НЕ подгоняй под green. **Severity — по ДОСТИЖИМОСТИ, не по факту падения:** воспроизводимо через публичный ТИПИЗИРОВАННЫЙ API → эскалируй src-фикс в `/bugfix` (ветка + changeset), issue про баг. Достижимо ТОЛЬКО type-violating misuse (any-cast/JS — тип запрещает; напр. #1411 interceptor без `next()`, #1412 async `onStart` при `() => void`) → **флагни как latent robustness-gap + рекомендуй guard**, заведи issue по запросу, НЕ заводи ветку/changeset ради него. Пометь в отчёте в обоих случаях; issue-claim про «isolation path, который просто не покрыт» может оказаться про НЕсуществующий path (grounding → triage-non-gap + latent-находка, а не пин).
- **Триаж-non-gap** (issue-claim не репродуцируется — ячейка уже покрыта / тест уже дискриминирует / мутант уже killed): корректный исход «проверено, гепа нет» — коммит не нужен, issue закрывается с объяснением. НЕ частичный провал, группой не блокируй.
- Не помечай группу выполненной при падающих тестах или недоказанной дискриминации хотя бы одного гепа.

## Итоговый отчёт

- Worktree: каталог вне репозитория; sha последнего коммита для `git merge --ff-only`.
- Таблица по гепам: `#<N>` → **класс** (missing / integrity / property / stress) → тест(ы) + **доказательство мутации** (что сломал → покраснело, что вернул → зелёно) → коммит → статус (**закрыт** / **not-reproduced** триаж / **BUG → эскалирован в `/bugfix` #NN**).
- Точечная валидация объединённого набора (полный граф — на pre-push; отметь поведенчески-затронутых потребителей, если баг всплыл в широком пакете).
- Коммиты: sha и `Closes #<N>` каждого гепа. Всплывшие баги — отдельные ветки/PR + changeset.
- Черновики issue-комментариев.

## Самокоррекция скила (журнал кандидатов)

Скил правится по накопленному, а не после каждого прогона: правка по одному инциденту описывает случай, а не класс, а платит за неё каждый следующий прогон.

1. **Запись в журнал, а не правка** — после отчёта. Где текст скила промолчал, был двусмыслен или неверен и это стоило вызовов, реплики владельца или риска ошибки, допиши строку в `.claude/skill-candidates/test-gap-batch.md` основного чекаута (gitignored; из worktree — `dirname "$(git rev-parse --path-format=absolute --git-common-dir)"`): дата, задача, раздел, класс (молчит / двусмыслен / неверен), инцидент, цена. Под `EnterWorktree` запись в основной чекаут отклоняется, а «копия в worktree», которую предлагает отказ, пропадёт вместе с worktree (`.claude/*` в `.gitignore`) — держи строку в scratchpad и перенеси её сам: `ExitWorktree` (`keep`), запись, `EnterWorktree` с `path` обратно. Строка того же класса уже есть — допиши инцидент к ней. В отчёте — одна строка: что записано.
2. **Правка созревает, когда класс повторился** — в другой задаче или сессии. Неверный факт текста (команда, флаг, путь, число) — исправление, а не правило: его предлагай сразу. Планка: правка предотвратила бы ошибку или сняла бы лишние шаги.
3. **Граница sub-скиллов ↔ test-gap-batch.** Метод одного property-теста → `/audit-pbt`; stress-порога → `/stress-scenarios`; мутации → `/mutation-score`; оркестрация группы → `/bugfix-batch`. Сюда — только батч-специфика тест-гепов (классификация, дискриминация-как-гейт, тест-vs-баг маршрут). Не дублируй.
4. **Правка не растит файл:** сначала заточи существующий абзац; новое правило называет, что в том же разделе сжато или удалено. Рост — только с согласия владельца.
5. **Предлагай, не применяй молча.** Созревшие правки — таблицей (раздел | инциденты из журнала | текст | что сжато), спроси разрешения; итог помечай в журнале. В скил — правило в настоящем времени, без номеров прогонов и дат; инциденты — в сообщение коммита. Применил по согласию → `.claude/commands/` infra, в master напрямую, без changeset.
6. **Ничего не записано и не созрело** — так и скажи одной строкой.
