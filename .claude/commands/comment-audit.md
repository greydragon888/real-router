Проаудируй КАЖДЫЙ комментарий одного файла по отдельности — многоагентно, через `Workflow` (ультракод): рой разбирает блоки, второй рой ПРОВЕРЯЕТ их утверждения замером, третий (адверсариальный) пытается опровергнуть каждую рекомендацию. Агенты не правят ничего — они возвращают **блок рекомендаций**. Реализует оркестратор: правки, гейты, коммит.

Входные данные:
$ARGUMENTS

Формат аргументов:
- Путь к файлу (`packages/core/src/namespaces/EventBusNamespace/EventBusNamespace.ts`). Один файл за прогон — рой масштабируется по числу блоков внутри него, а не по числу файлов.
- Опционально `--dry` — остановиться на блоке рекомендаций, без правок и коммита.
- Опционально `--no-mutate` — запретить мутационные замеры (быстрый прогон: только адреса, дубли, соответствие коду). Вердикт «избыточно» тогда ЗАПРЕЩЁН — см. §Гейт.

Пример:
```
/comment-audit packages/core/src/namespaces/NavigationNamespace/transition/executeNavigation.ts
/comment-audit packages/core/src/routerFSM.ts --dry
```

## Принцип

Комментарий — это **обязательство**, а не украшение. Самая дорогая его форма отказа — не многословие, а **ложь**: счётчик, перемеренный в другом месте и не обновлённый здесь; адрес теста, который переименовали; утверждение об отсутствии, которое отменил соседний коммит; вывод, отменённый закрытым расследованием. Ложный комментарий хуже отсутствующего: он тратит доверие ровно там, где читателю нечем проверить.

Второй по цене режим — **комментарий не у своего кода**: тридцать строк про гейт над строкой, которая гейтом не является; примечание про `Object.freeze` за тридцать строк до самого `Object.freeze`. Третий — **дубль**: один факт, изложенный в трёх-пяти местах, из которых расходиться начнут все, кроме одного.

Поэтому аудит идёт не по объёму, а по **истинности → адресности → уникальности → и лишь потом длине**.

## Классификация (единственная ось, по которой судят блок)

| категория | признак | что с ней делают |
| --- | --- | --- |
| **ДЕРЖИТ** | называет инвариант с режимом отказа: «сломается так-то, если…» | оставить; проверить, что он и правда держится (замер), и что число в нём сегодняшнее |
| **ОБЪЯСНЯЕТ** | называет механизм или отвергнутую альтернативу, которых из кода не видно | оставить, если стоит у своего кода и не повторён у владельца |
| **АРХИВ** | рассказывает, что было ДО (переезды, удалённые предикаты, история счёта) | снять или свернуть до ссылки на issue; история живёт в git и IMPLEMENTATION_NOTES |
| **ОПИСЫВАЕТ** | пересказывает соседние строки кода | снять |

Операционально: если из абзаца нельзя извлечь **проверяемое утверждение** и он не называет **режим отказа** — это не «держит».

## Дисциплина замера (ядро; нарушение обесценивает весь прогон)

- **Вердикт «избыточно» требует ДВУХ измерений: тестов И покрытия ветвей.** Ноль красных ≠ избыточно. Реальный случай: строка, чей собственный ⚠ объявлял её «больше не инвариантом», при удалении не роняла ни одного из 4097 тестов — и роняла покрытие со 100 % до 99,94 %, потому что была единственным потребителем ветки идемпотентности. Мерить `--coverage.enabled=true` всегда.
- **Утверждение об отсутствии проверяется сканом, а не чтением**: «единственный `new X()`», «нигде не обнуляется», «нет второго читателя» — `grep`/AST по пакету, с числом в ответе.
- **Адреса проверяются существованием**: имя теста (файл + название кейса), путь, номер строки, `{@link}`. Битый адрес — находка уровня ЛОЖЬ.
- **Счётчики перемеряются**: «роняет 5 тестов», «пять `emitTransition*`», «206 раз за тир». Суита растёт; число, названное полгода назад, почти наверняка другое.
- **Дубли ищутся по всему пакету**, а не по файлу: один и тот же факт живёт у ВЛАДЕЛЬЦА — там, где стоит код, о котором факт. Остальные копии → одна строка-указатель.
- **Числа дороже слов.** Сокращая, сохраняй измеренные величины и адреса пинов; выбрасывай прозу вокруг них.

## Фазы (скрипт для `Workflow`)

**Фаза 0 — инвентарь (оркестратор, без роя).** Детерминированным сканом собери: каждый блок комментария (адрес `строка-строка`, тип — JSDoc/строчный, размер), к какому объявлению он прилегает, маркеры (⚑/⚠/⛔), метрики код/проза по файлу и по каждой функции. Сними baseline: тир зелёный, покрытие 100 %.

⛔ **Инвентарь ВПЕЧАТЫВАЕТСЯ в скрипт литералом, а не едет через `args`.** Переданный строкой JSON приходит в скрипт строкой, и `pipeline()` падает на первой же строке с `expects an array` — проверено, первый прогон этого скилла умер за 47 мс, ноль агентов. Сгенерируй тело скрипта скриптом же: инвентарь → `const BLOCKS = [...]` внутри исходника воркфлоу.

**Фаза 1 — разбор (рой, ОДИН агент на ОДИН блок).** Гранулярность — это и надёжность, и скорость: агент с одним предметом не размывает контекст (в первом прогоне ошибся ровно тот агент, которому досталось семь блоков и 256 строк прозы), а внутри агента работа последовательная, поэтому тридцать мелких при параллелизме ~10–16 идут вдвое-втрое быстрее трёх крупных. Батчить по 2–3 блока — только когда блоков больше сорока; группировать «по смыслу» НЕ надо, блок самодостаточен.

Каждый агент по СВОЕМУ блоку:
1. разложить на атомарные утверждения;
2. классифицировать каждое (таблица выше);
3. для проверяемых — сформулировать конкретную проверку: точную мутацию и ожидаемый результат, либо скан;
4. найти адреса и копии факта (grep по пакету);
5. вернуть структурой: `claims[] {text, category, checkable, proposedCheck, addresses[]}`, `duplicates[]`, `misplaced: bool`, `draftReplacement`, `linesBefore/After`.

**Фаза 2 — проверка (рой, 1 агент на блок, но ТОЛЬКО для блоков с проверяемыми утверждениями).** Отфильтруй в скрипте: `blocks.filter(b => b.claims.some(c => c.checkable))` — обычно это половина. Агент ВЫПОЛНЯЕТ то, что фаза 1 только предложила: скан → число, адрес → открыть файл и убедиться. Мутации он НЕ запускает: в одном рабочем дереве параллельные мутации конфликтуют, а свежий git-worktree не годится (там нет `node_modules`, `vitest` не поднимется). Поэтому мутации возвращаются оркестратору данными — `{anchor, replacement, expected}` — и тот прогоняет их последовательно.

Возвращает `verdict: TRUE | FALSE | STALE | UNMEASURED` с фактическими числами. `UNMEASURED` НЕ может служить основанием для удаления.

**Фаза 3 — критика (адверсариальный рой, 3 линзы на ПАКЕТ рекомендаций).** Не по три критика на каждый блок — это множит рой вчетверо без прироста качества. Собери выжившие рекомендации в пакеты по 6–10 (по смежным блокам) и дай каждому пакету три линзы. Задача — опровергнуть:
- **линза «утрата»**: что перестанет быть известно, если это убрать? Восстановимо ли из кода, типов, тестов? Если знание живёт только здесь — рекомендация отклоняется;
- **линза «метод»**: воспроизводится ли замер? не спутано ли «0 красных» с «избыточно» (проверено ли покрытие)? не мерил ли агент не то, что утверждает?
- **линза «самостухание»**: не содержит ли предложенный текст нового счётчика/адреса, который протухнет так же? не переносит ли он ложь в другую формулировку?
Рекомендация проходит при большинстве «не опровергнуто». Отклонённые попадают в отчёт с причиной — они тоже результат.

**Фаза 4 — синтез (один агент), и он получает ВЫЖИМКУ, а не сырой JSON.** Это узкое место: сырые результаты роя не влезают в один промпт, и обрезка режет молча. В первом прогоне `slice(0, 40000)` съел две трети — синтезатор увидел одну группу из трёх, сообщил об этом сам и перевыводил остальное вручную. Поэтому **скрипт сжимает перед синтезом**: из каждого блока — только `{at, defectClass, whatIsWrong, evidence, anchorText, replacement, linesSaved, refutedBy[]}`, без исходных текстов комментариев и без промежуточных рассуждений. Если выжимка всё равно велика — синтезируй в два уровня (по 10 блоков → частичные отчёты → финальный), а не режь строкой.

Итог — **блок рекомендаций**, отсортированный по убыванию цены дефекта: `ЛОЖЬ → ДУБЛЬ → НЕ У СВОЕГО КОДА → АРХИВ → ОБЪЁМ`. Для каждой: адрес, что не так, чем доказано (число!), предлагаемый текст, сколько строк экономит, риск.

**Реализация — оркестратор, не рой.**

1. ⛔ **Каждую находку класса ЛОЖЬ перепроверь САМ, до правки.** Рой ошибается ровно там, где выглядит увереннее всего: в первом прогоне верификатор объявил «три отправителя FAIL» вместо двух, посчитав в ту же корзину отправителя, который `nav` не несёт. Одна такая ошибка, применённая без проверки, превращает аудит истинности в источник новой лжи. Скан/чтение занимают минуту.
2. Прогони мутации, которые рой вернул данными, — последовательно, с откатом файла после каждой.
3. Применяй правки скриптом с якорями (не построчно), после каждой группы: `prettier --check` → `eslint` → `tsc --noEmit` → тир **с покрытием**.
4. Коммит по правилам репо. Ни один агент роя не пишет в файлы.

⚠ **Если синтез вернул неполный отчёт — источник истины `journal.jsonl` воркфлоу.** Там лежит по строке `{"type":"result",…}` на каждого завершившегося агента, со всем возвратом целиком. Достань недостающие группы оттуда, а не перезапускай рой.

Шаблон скрипта (`BLOCKS` — литерал, впечатанный фазой 0):

```js
export const meta = {
  name: 'comment-audit',
  description: 'Per-comment audit of one file: analyse → verify → criticise → recommend',
  phases: [
    { title: 'Analyse', detail: 'one agent per comment block' },
    { title: 'Verify', detail: 'settle the checkable claims' },
    { title: 'Criticise', detail: 'three lenses per package of recommendations' },
    { title: 'Synthesise', detail: 'one ranked recommendation block' },
  ],
}

const BLOCKS = [/* впечатано фазой 0: {at, len, attachedTo, markers} */]
const FILE = '/абсолютный/путь'          // тоже литерал, не args

// 1+2: разбор и проверка идут ПО БЛОКУ, без барьера между ними
const perBlock = await pipeline(
  BLOCKS,
  b => agent(ANALYSE(FILE, b), { label: `analyse:${b.at}`, phase: 'Analyse', schema: BLOCK_SCHEMA }),
  (r, b) => (r?.claims ?? []).some(c => c.checkable)
      ? agent(VERIFY(FILE, b, r), { label: `verify:${b.at}`, phase: 'Verify', schema: VERDICT_SCHEMA })
          .then(v => ({ block: b, analysis: r, verification: v }))
      : { block: b, analysis: r, verification: null },
)

// 3: критика по ПАКЕТАМ, а не по блокам — иначе рой множится вчетверо
const alive = perBlock.filter(Boolean)
const packs = []
for (let i = 0; i < alive.length; i += 8) packs.push(alive.slice(i, i + 8))

const judged = await parallel(
  packs.flatMap((pack, i) =>
    ['loss', 'method', 'rot'].map(lens => () =>
      agent(CRITIQUE(FILE, digest(pack), lens), {
        label: `critique:${i}:${lens}`, phase: 'Criticise', schema: CRITIQUE_SCHEMA,
      }))),
)

// 4: синтез получает ВЫЖИМКУ (digest), не сырые результаты
return await agent(SYNTHESISE(digest(alive), judged.filter(Boolean)), {
  phase: 'Synthesise', schema: REPORT_SCHEMA,
})
```

`digest()` — обычная JS-функция в скрипте: оставляет `{at, defectClass, whatIsWrong, evidence, anchorText, replacement, linesSaved}` и выбрасывает исходные тексты и рассуждения. Именно она держит синтез в пределах одного промпта; `slice()` по строке — не замена, он режет молча и посреди объекта.

## Что рекомендовать помимо сокращения

- **Перевод инварианта из прозы в тип или скан.** Если абзац предписывает порядок («ask должен стоять выше cleanup»), спроси: выражается ли он `unique symbol`-брендом, обязательным параметром, `const`, который нельзя прочесть выше объявления? Если да — рекомендуй правку КОДА, а не текста; компилятор говорит раньше теста и не устаревает.
- **Скан тела вместо прозы**, когда инвариант — про отсутствие (`«на этой арке нет контроллера»`): поведенческий тест такого не видит, AST-скан видит.
- **Переименование вместо объяснения.** Параметр `isCurrentNav`, в который передают `() => !signal.aborted`, порождает семь строк прозы; переименование убирает их все.
- **Маркеры**: ⚠ — там, где назван режим отказа; ⚑ — там, где назван владелец инварианта. На архивном абзаце маркера быть не должно: знак, встречающийся раз на тридцать строк, перестаёт выделять.

## Гейт (обязателен перед реализацией)

1. Каждая рекомендация несёт **число или адрес** — либо помечена `UNMEASURED` и тогда только смягчает формулировку, не удаляет.
2. Ни одна не удаляет знание, которое фаза 3 признала невосстановимым.
3. Baseline воспроизведён после правок: тир зелёный, **покрытие не упало**.
4. При `--no-mutate` вердикты «избыточно»/«не держится» запрещены — только ЛОЖЬ/ДУБЛЬ/АДРЕС.

## Размер роя и цена

Считай до запуска: `N` блоков → `N` analyse + `~N/2` verify + `3·⌈N/8⌉` критиков + 1 синтез. Для файла на 30 блоков это ~50 агентов и порядка нескольких миллионов токенов; для файла на 10 — около 17. Прогон в 16 агентов над 32 блоками стоил 2,8 млн токенов и 44 минуты, и его узким местом была именно НЕ-гранулярность: агенты с семью блоками ошибались чаще, а синтез захлебнулся.

Если размер роя выходит за отведённое сессии — режь **не гранулярность фазы 1**, а объём: возьми половину файла (верхние N блоков) и прогони вторую половину отдельным заходом. Один блок = один агент — то, что делает результат воспроизводимым.

## Жёсткие правила

- Агенты роя **read-only**: никаких `Edit`/`Write` в исходники. Их продукт — рекомендации.
- Один файл за прогон; рой масштабируется числом блоков, ОДИН агент на блок.
- Инвентарь — литерал в скрипте. `args` строкой убивает прогон на первой строке.
- Синтез получает выжимку. Обрезка строкой — молчаливая потеря данных.
- Каждую ЛОЖЬ оркестратор перепроверяет сам перед правкой.
- Мутация всегда откатывается — восстановление файла в `finally`-стиле, до следующей.
- «0 красных» без покрытия — не вердикт.
- Не выбрасывать измеренные числа при сокращении: они — то, что нельзя переоткрыть чтением.
- Не push, не PR. Коммит — по модели доставки репо (docs/refactor в `master` напрямую).
