Подготовь RFC, сошедшийся по дельте, к полному аудиту или к реализации: заархивируй полную версию, сверни решения владельца в реестр с прежними номерами, убери журнал, метки раундов аудита и закрытое, сохрани доказательства, ASSUMPTION и открытые проверки — и проверь чистовик на внутренние противоречия.

Входные данные:
$ARGUMENTS

Формат аргументов:

- Путь к RFC (напр. `.claude/ci-cd-architecture-2026-09-29/rfc/rfc-3-derived-config.md`).
- Опционально `--for audit` (по умолчанию) или `--for implement` — для чего чистовик: следующий шаг — полный `/audit-rfc` или `/implement-rfc`.
- Опционально `--dry-run` — архив не трогать, текст не править: замер, опись и план преобразования.

Пример:

```
/clean-rfc .claude/ci-cd-architecture-2026-09-29/rfc/rfc-3-derived-config.md
/clean-rfc .claude/ci-cd-architecture-2026-09-29/rfc/rfc-1-single-check-runner.md --for implement
```

> **Соседние скилы.** `/audit-rfc` находит дефекты и в режиме `--delta` сверяет правки, пока сверка не перестанет находить BLOCKER; этот скил идёт после такой сходимости. Дальше — полный `/audit-rfc` по чистовику или `/implement-rfc`.

---

## Принцип

Документ, прошедший десятки раундов «аудит → правка → сверка», наполовину состоит из истории: разборов вариантов, пометок «решено владельцем», меток находок, зачёркнутого, журнала. Полному аудиту она мешает: аудитор судит путь к решению, а не дизайн, и привязывается к прежней постановке — а именно то, что изначально не рассматривалось, и должен найти полный аудит. Реализации она мешает так же: исполнителю нужен план, а не его родословная.

Чистовик — то же содержание в настоящем времени. Это **преобразование, а не вычёркивание**: итог каждого решения остаётся, разбор уходит в архив; закрытое уходит, а открытое — проверки, ждущие прогона, ASSUMPTION, вопросы без ответа — остаётся и становится заметнее. История живёт в одном месте — в архиве, — как в правиле CLAUDE.md о докблоках.

(Прогон RFC-3 R69 → чистовик, 2026-10-02: 21 753 → 10 664 слова; §10 и журнал были 49 % текста; 243 метки истории вне журнала → 0, кроме намеренных ссылок на архив.)

## Когда запускать

- **Документ сошёлся по дельте:** последняя `/audit-rfc --delta` не нашла BLOCKER, решения владельца внесены. Не сошёлся — остановись и скажи: чистка спрячет открытые находки вместе с историей.
- **Прочитай документ целиком до первой правки.** Поздняя ревизия меняет смысл ранних разделов; опись (фаза 2) без полного чтения теряет перенос содержимого.
- Документы под `.claude/` обычно не отслеживаются git: архив — единственная запись истории.

## Фаза 1 — Архив

1. Скопируй полную версию в `<каталог исследования>/archive/<имя>.R<N>.md` — вне папки, которую читает аудитор. Туда же — каждый индекс, который будешь править (`<имя индекса>.before-<документ>-clean.md`).
2. Сверь sha256 копий с оригиналами.
3. Заведи или дополни `archive/README.md`: что лежит, и «⚠ при полном аудите этот каталог не читать».

После этого архив не правится.

## Фаза 2 — Замер и опись

Помощник замера — сохрани в scratchpad и гоняй до правок (база) и после (гейт). Разделы он находит по заголовку, не по номеру: у разных RFC «Открытые вопросы к владельцу» — §8, §9 или §10. Журнал кончается на любом заголовке второго уровня: приложение после него — тело, и его метки проходят оба гейта. (RFC-3 R85: при конце журнала только на нумерованном заголовке приложение А считалось журналом, и замер видел 7 меток истории из 11.)

```python
# rfc-measure.py <doc.md> [--archive <full-version.md>]
import re, sys
from collections import Counter

DECISIONS = re.compile(r"^## (\d+)\. (Открытые вопросы к владельцу|Решения владельца)")
JOURNAL = re.compile(r"^## \d+\. Журнал ревизий")
EVIDENCE = re.compile(r"\[(изм|прочит|проба|вывод|отч|док|поиск)[^\]]*\]")
TAGS = re.compile(r"(BLOCKER|SHOULD-FIX|MINOR)[^.;\n]{0,40}аудит|\b[SB]\d{1,2} аудит|аудит[а-я]*-дельт|\bR\d{1,3}\b"
                  r"|решено|снято|сведено|пересмотрено|✅|~~|Было:")


def split(path):
    lines = open(path, encoding="utf-8").read().split("\n")
    body, dec, jour, num, part = [], [], [], None, "body"
    for l in lines:
        m = DECISIONS.match(l)
        if m:
            part, num = "dec", m.group(1)
        elif JOURNAL.match(l):
            part = "jour"
        elif re.match(r"^## ", l):
            part = "body"
        {"body": body, "dec": dec, "jour": jour}[part].append(l)
    return "\n".join(body), "\n".join(dec), "\n".join(jour), num


def words(t):
    return len(t.split())


doc = sys.argv[1]
body, dec, jour, num = split(doc)
total = words(body) + words(dec) + words(jour)
print(f"слов: {total}; решения: {words(dec)} ({words(dec) * 100 // max(total, 1)}%); журнал: {words(jour)} "
      f"({words(jour) * 100 // max(total, 1)}%)")
if num:
    refs = Counter(re.findall(rf"§{num} п\. ?(\d+)", body + "\n" + dec))
    items = set(re.findall(r"^(\d+)\. ", dec, re.M))
    print(f"ссылок «§{num} п. N»: {sum(refs.values())}; пунктов в разделе: {len(items)}; "
          f"висячих: {sorted(set(refs) - items, key=int) or 'нет'}")
tags = [m.group(0) for m in TAGS.finditer(body + "\n" + dec)]
print(f"метки истории вне журнала: {len(tags)} {dict(Counter(tags).most_common(8))}")
print(f"метки доказательств в теле: {len(EVIDENCE.findall(body))}; ASSUMPTION в теле и решениях: "
      f"{len(re.findall('ASSUMPTION', body + dec))}")
start = cur = None
for i, l in enumerate(open(doc, encoding="utf-8"), 1):
    if l.startswith("|"):
        n = len(re.split(r"(?<!\\)\|", l.rstrip("\n"))) - 2
        if cur is None:
            cur, start = n, i
        elif n != cur:
            print(f"ширина таблицы: строка {i} — {n} столбцов, у таблицы со строки {start} — {cur}")
    else:
        cur = None
if "--archive" in sys.argv:
    abody, adec, _, _ = split(sys.argv[sys.argv.index("--archive") + 1])
    ca = Counter(m.group(0) for m in EVIDENCE.finditer(abody))
    cb = Counter(m.group(0) for m in EVIDENCE.finditer(body))
    lost = ca - cb
    print(f"метки доказательств тела, которых нет в чистовике: {sum(lost.values())}")
    for k, v in lost.items():
        print(f"  {v}× {k[:110]}")
    print(f"ASSUMPTION: в архиве (тело и решения) {len(re.findall('ASSUMPTION', abody + adec))}, "
          f"в чистовике {len(re.findall('ASSUMPTION', body + dec))}")
```

Опись — до правок, таблицей:

- **Каждый пункт раздела решений:** итог одной строкой; «почему» — одно-два предложения; цена; ASSUMPTION; условие («если X — то Y»); открытый подвопрос; определения, которыми пользуется тело (наборы, термины); содержимое, на которое тело ссылается (перепись, таблица), — и куда оно переезжает.
- **Закрытое** (✅ «снято», «сведено», «выполнено», зачёркнутое): на каждый ID — поиск ссылок ДО удаления строки. Выполненное, у которого открыта проверка (плановый прогон, первый fork-PR, первый релиз), не закрыто: остаётся с пометкой «выполнено» и открытой проверкой.
- **Метки:** номер находки (`S12`, `B2`, `SHOULD-FIX 3`, `R54`) уходит; метка, которой текст пользуется как термином (`F2`, «класс B2», наборы `P`/`L`/`D`), остаётся — и определяется там, где встречается впервые.

При `--dry-run` остановись здесь: отчёт — замер, опись, план.

## Фаза 3 — Преобразование

Правь скриптом точных замен, где каждая замена проверяет ровно одно совпадение; никакого удаления по шаблону вслепую.

- **Статус** — две-три строки: «чистовик для полного аудита» (или «для реализации»), дата, «содержание ревизии R<N> без истории; полная R<N> — `<путь архива>`, при аудите не читать», волна и одобрение.
- **Раздел решений → реестр «Решения владельца» с прежними номерами пунктов.** Пункт: итог жирным, «Почему:» одним-двумя предложениями, цена и ASSUMPTION, если были; без вариантов, отвергнутого и истории пересмотров. Вопросы без ответа — в блок «Открыто» в конце раздела. Удалять раздел целиком нельзя: ссылки «§N п. M» в теле повиснут, а их переписывание — новый источник дефектов. (RFC-3: 65 ссылок; реестр сохранил их все.)
- **Содержимое, жившее только в разборе, но нужное телу**, переезжает к первому читателю, ссылки на него правятся. (RFC-3: перепись копий набора workspace — из §10 п. 8 под таблицу §5; висячую ссылку «перепись в §10 п. 8» в таблице D1 нашёл поиск после переноса.)
- **Журнал** уходит целиком — он в архиве.
- **Метки раундов аудита, ссылки на ревизии, «решено владельцем <дата>: (x)», «пересмотрено»** — уходят; «(§N п. M — (x))» становится «(§N п. M)».
- **Повествование** — «Было:», «исправлено в `<sha>`», «удалён в `<sha>`», «с `<sha>`», «Rk исправляет Rj» — переписывается в настоящем времени или уходит. Коммит, который доказывает нынешнее состояние, остаётся.
- **Закрытые строки и шаги** уходят; номера не перенумеровываются, пропуски объясняет одна строка под таблицей.
- **Остаётся:** метки доказательств (`[изм]`, `[прочит]`, `[проба <дата>]` — из них уходит только метка аудита внутри скобок); ASSUMPTION; открытые проверки; одобрение и решения как состояние. Если в метке нет ничего, кроме номера ревизии (`[R84]`), вид доказательства бери из архива — из версии, где утверждение появилось, — или перепроверь; наугад не ставь. (RFC-3 R85: у `[R84]` при оценке роадмапа в R84 стояло `[прочит 2026-10-02: …]`, число подтвердил #296.)
- **Индекс**, пересказывающий историю этого документа, — сокращается до состояния и указателя на архив. Соседние документы не правятся.

## Фаза 4 — Проверки

1. **Замер против базы:** `rfc-measure.py <чистовик> --archive <архив>`. Метки истории — ноль, кроме намеренных ссылок на архив; висячих ссылок «§N п. M» нет; ширины таблиц целы.
2. **Потерянные метки доказательств и ASSUMPTION:** каждая потерянная метка тела — либо из удалённого закрытого, либо осталась в сокращённой форме. ASSUMPTION — все до одной. ⚠ Сжатие пункта реестра теряет оговорку незаметно: сверь каждый пункт с его разбором в архиве — ASSUMPTION, цена, условие, открытый подвопрос, определения. (RFC-3: сжатие п. 6 потеряло ASSUMPTION о частоте находок `prose-lint`; нашёл счёт меток: 1 из 2.)
3. **Ссылки на удалённое:** поиск по каждому удалённому ID и номеру шага — ноль, кроме строки о пропусках.
4. **Адреса:** файлы, которые называет документ, не менялись после последней сверки адресов (`git log <коммит сверки>..HEAD -- <файлы>`), а адреса перенесённого содержимого сверены на HEAD по точному тексту.
5. **Внутренние противоречия** — сверка разделов друг с другом, а не с историей:
   - каждый пункт DoD — против правила цели, которое он пересказывает (RFC-3: DoD требовал решения владельца по живым расхождениям T5 и T12, а Ц3 — по каждому; T8, T11 и T13 выпали — противоречие было и в R69);
   - перечень в TL;DR — против перечня в теле;
   - число, записанное дважды;
   - утверждение «каждый X» над списком — поштучно;
   - классы находок прошлых раундов — по журналу архива, как классы, а не экземпляры — ещё раз по чистому тексту.
6. **Остатки истории в словах:** «теперь», «прежние», «больше не», «снова», «до правки» — каждое должно описывать проверку или нынешнее состояние, а не путь.

## Фаза 5 — Отчёт и передача

- Архив: пути и sha256; размер до и после; что переехало и куда; что осталось открытым.
- Противоречия раздельно: найденные в прежнем тексте (исправленные механически или вынесенные владельцу) и внесённые чисткой (исправленные).
- Следующий шаг: при `--for audit` — полный `/audit-rfc <документ>`, не `--delta`: база дельты — сохранённая копия прошлой версии, а чистовик отличается от неё формой во всех разделах. Аудитору — читать только документ и дерево: архив, индекс и память проекта хранят прошлые находки. При `--for implement` — `/implement-rfc <документ>`; блок «Открыто» не должен касаться шагов, которые идут в реализацию.
- Память проекта по этому RFC — где архив, что открыто.

## Жёсткие правила

- Не чистить документ, который не сошёлся по дельте.
- Архив — до первой правки; после — не трогать.
- Раздел решений сворачивать в реестр, не удалять; номера пунктов и шагов не менять.
- Не терять открытое: проверки, ждущие прогона, ASSUMPTION, вопросы без ответа.
- Ссылки на ID — искать до удаления строки.
- Аудит в этом же прогоне не проводить: чистовик проверяет следующий шаг.
- Правки RFC changeset не требуют. Push — только по явной просьбе.

## Самокоррекция скила (ОБЯЗАТЕЛЬНО, в конце КАЖДОГО прогона)

Этот файл — живой; каждый прогон обязан его затачивать. После отчёта вынеси короткую секцию **«Самокоррекция»** — критику не своей работы, а САМОГО ЭТОГО СКИЛА: где его текст промолчал, соврал, был двусмыслен или избыточен — и это стоило времени, лишнего шага или риска ошибки.

1. **Привязка к ИНЦИДЕНТУ, не общие советы.** Каждая правка — из конкретного момента ЭТОГО прогона: «скил сказал X / промолчал про X → реальность Y → я потерял/чуть не ошибся на Z». Нет инцидента — нет правки.
2. **Высокая планка: изменило бы исход?** Предлагай, только если правка реально предотвратила бы ошибку, сократила перебор или сняла двусмысленность.
3. **Разовое ≠ паттерн.** Специфику конкретного RFC — в отчёт и память по нему, не в скил.
4. **Сначала заточи, потом дописывай.** Усиливай существующий абзац, а не добавляй новую секцию; избыточное — консолидируй.
5. **Предлагай, не применяй молча.** Кандидаты — таблицей (раздел | инцидент | предлагаемый текст), с вопросом. Применил по согласию → `.claude/commands/` — инфраструктура, в master напрямую, без changeset.
6. **Честность про «нечего править».** Прогон прошёл чисто — так и скажи: «правок нет».
