Выпусти работу над задачей: закоммить её, переведи ветку на свежий `master`, запушь, открой PR и опубликуй комментарий к задаче — в этом порядке.

Входные данные (опционально):
$ARGUMENTS

Без аргументов — самый частый вызов — всё берётся из контекста сессии. Можно передать:

- путь к worktree или имя ветки — иначе worktree, в котором стоит сессия; ветку по имени находит `git worktree list`;
- `#N` — задачу; иначе ведущее число имени ветки (`<N>-<slug>`), сверенное с заголовками коммитов и первой строкой changeset ветки, как в `/create-pr` Фаза 1;
- путь к черновику комментария — иначе тот, что назвал отчёт вызвавшей команды (`/bugfix` Фаза 7).

Вызов — явная просьба закоммитить работу задачи, запушить ЭТУ ветку, открыть PR и опубликовать комментарий. `master`, чужую ветку, force-push и `--no-verify` он не разрешает.

## Почему такой порядок

- **Коммит первым.** Pre-push отказывает, если рабочее дерево не пусто; `pnpm lint:security` берёт дельту из коммитов ветки; PR и комментарий описывают закоммиченный код.
- **Rebase до пуша.** Пока ветки нет на remote, `git rebase origin/master` обходится без force-push, и pre-push собирает ту базу, в которую уйдёт PR. `/create-pr` (Фаза 0 п. 5) перебазирует только ветку, которой ещё нет на remote.
- **PR до комментария.** Комментарий ссылается на номер PR.

Под `EnterWorktree` харнесс отклоняет команду, которую не может проверить, — git с переменной или в цикле, heredoc: `git -C <worktree>` с буквальным путём, длинное — скриптом-файлом в scratchpad.

## Шаг 0 — Состояние

Одним вызовом: `git -C <wt> branch --show-current`, `git -C <wt> status --short --untracked-files=all`, `git -C <wt> log --oneline origin/master..HEAD`, `gh pr view <branch> --json number,url,state`.

- Ветка `master` или дифф — инфраструктура по правилу CLAUDE.md («Infrastructure tasks go straight to `master`»): PR ему не место. Скажи это и остановись.
- Дифф трогает `packages/*/src` или `shared/<dir>`, а `.changeset/*.md` в ветке нет — сначала `/changeset` (Skill): `changeset-check.yml` откажет PR без него.
- PR ветки уже `OPEN` — `/create-pr` в шаге 4 второго не создаст и предложит обновить тело.

## Шаг 1 — Коммит

1. Каждый файл из `status` относится к задаче; пробы (`__probe*`, отладочные файлы) удали до `add`. В worktree задачи — `git -C <wt> add -A`, иначе поимённо.
2. Сообщение — от `/commit-msg` (Skill) по `git -C <wt>`; его вывод в этой сессии годится, если дифф с тех пор не менялся. До коммита: `pnpm --dir <wt> exec commitlint < <file>`.
3. `git -C <wt> commit -F <file> > <log> 2>&1; echo "rc=$?"` — в фоне: pre-commit гоняет тесты и линт затронутых пакетов. Вердикт — `rc=` в выводе.
4. Провал хука оставляет индекс: перед повтором — `git status --short`. После коммита — `git show --stat HEAD` и пустой `status`.

## Шаг 2 — Свежая база

1. `git -C <wt> fetch origin`; есть ли ветка на remote — `git -C <wt> ls-remote --heads origin <branch>`.
2. Ветки на remote нет, а `git -C <wt> merge-base --is-ancestor origin/master HEAD` отвечает кодом 1 — `git -C <wt> rebase origin/master`. Конфликт — по `/create-pr` Фаза 0 п. 5 или сообщи и остановись. `master` принёс новый `pnpm-lock.yaml` — `pnpm install --frozen-lockfile` в worktree до хуков.
3. Ветка уже на remote — не перебазируй: понадобился бы force-push. Расхождение с `master` решает `/create-pr`.
4. Rebase меняет SHA: текст, который его цитирует, перечитай.

## Шаг 3 — Пуш

1. `pnpm --dir <wt> lint:security` — на закоммиченном фиксе.
2. `git -C <wt> push -u origin HEAD > <log> 2>&1; echo "exit=$?" >> <log>` — в фоне: pre-push — полная сборка и колонка линтеров. Вердикт — строка `exit=` в логе и `git ls-remote --heads origin <branch>`, а не статус фоновой задачи. Обрыв SSH и упавший тест, к ветке не относящийся, — по `/create-pr` Фаза 4 п. 2.
3. Падение pre-push настоящее: чини новым коммитом через шаг 1 и пушь снова. Pre-push собирает `dist` в worktree: перед следующими тестами там — `rm -rf packages/*/dist && pnpm install`.

## Шаг 4 — PR

`/create-pr` (Skill) с брифом: ветка и worktree, задача `#N` (решена), кто пушил — SHA и `exit=0` pre-push, что измерено какой командой и на каком коммите. Правки вики задачи — строкой `After merge:`: вики документирует `master`, страницу правят после мержа. Запушенную ветку `/create-pr` повторно не пушит (Фаза 4 п. 2).

## Шаг 5 — Комментарий

1. Черновик сверь с опубликованным: статус — «In PR #M, not merged yet», а не merged или released; SHA — только запушенные; номера follow-up задач — заведённые.
2. `gh issue comment <N> --repo greydragon888/real-router --body-file <file>`; выведи URL.
3. Черновика нет — напиши его по `/bugfix` Фаза 7 п. 1 и опубликуй; текст — в отчёт.
4. Задач в ветке несколько — по черновику на задачу.

## Отчёт

- Коммит (SHA после rebase), pre-push (`exit=`), URL PR, URL комментария.
- Что осталось: `After merge:` — вики: только свои страницы (`git -C <wiki> add <pages>`), три чекера из чекаута вики с `REAL_ROUTER_ROOT=<repo>` (`node check-links.mjs`, `node check-messages.mjs`, `node check-code.mjs`), push; `git worktree remove` после мержа; незапушенные коммиты локального `master`, если есть.
- Журнал самокоррекции: что записано, или «ничего».

## Самокоррекция скила (журнал кандидатов)

Скил правится по накопленному, а не после каждого прогона: правка по одному инциденту описывает случай, а не класс, а платит за неё каждый следующий прогон.

1. **Запись в журнал, а не правка** — после публикации комментария. Где текст скила промолчал, был двусмыслен или неверен и это стоило вызовов, реплики владельца или риска ошибки, допиши строку в `.claude/skill-candidates/release-issue.md` основного чекаута (gitignored; из worktree — `dirname "$(git rev-parse --path-format=absolute --git-common-dir)"`): дата, задача, раздел, класс (молчит / двусмыслен / неверен), инцидент, цена. Под `EnterWorktree` запись в основной чекаут отклоняется: держи строку в scratchpad и перенеси сам — `ExitWorktree` (`keep`), запись, `EnterWorktree` с `path` обратно. Этот выход владелец просит заранее: не переспрашивай. Строка того же класса уже есть — допиши инцидент к ней. В отчёте — одна строка: что записано.
2. **Правка созревает, когда класс повторился** — в другой задаче или сессии. Неверный факт текста (команда, флаг, путь, число) — исправление, а не правило: его предлагай сразу.
3. **Разовое ≠ паттерн.** Специфику одной ветки — в память, не в скил.
4. **Правка не растит файл:** сначала заточи существующий абзац; новое правило называет, что в том же разделе сжато или удалено. Рост — только с согласия владельца.
5. **Предлагай, не применяй молча.** Созревшие правки — таблицей (раздел | инциденты из журнала | текст | что сжато), спроси разрешения; итог помечай в журнале. Применил по согласию → `.claude/commands/` это infra, в master напрямую, без changeset. ⚠ В сообщении такого коммита не ставь закрывающее слово (close/fix/resolve) вплотную к `#N`: push в `master` закроет задачу.
6. **Ничего не записано и не созрело** — так и скажи одной строкой.
