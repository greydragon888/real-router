Глубокий разбор turbo-телеметрии CI (Grafana Cloud Prometheus): найди инсайты, аномалии и возможности оптимизации — и подтверди каждую причину пробой, прежде чем назвать её причиной.

Входные данные:
$ARGUMENTS

Формат аргументов (всё необязательно): фокус (джоба, пакет, задача, событие), окно (`7d` по умолчанию; в Free-тарифе метрики живут 14 дней), `--quick` — только инвентаризация и топ-находки без локальных проб.

> **Это НЕ `/perf-optimize`.** Тот меряет код рантайма. Здесь предмет — CI и инструменты: время задач turbo, кеш, конкуренция за CPU, дрейф тулчейна, качество самой телеметрии.

## Фаза 0 — Доступ, не печатая секретов

Данные: turbo шлёт OTLP → nginx → OTel Collector на `77.222.38.47` (`/opt/real-router-telemetry`, конфиг как код — `ops/telemetry/`) → Grafana Cloud Prometheus. Подробности — IMPLEMENTATION_NOTES, записи #1745.

- Чтение: `GRAFANA_PROM_URL` и `GRAFANA_PROM_LOGIN` (логин уже `user:token`) в `~/.zshrc`. Bash-тул видит снимок `~/.zshrc` со старта сессии, поэтому строки грузятся в подоболочке. ⛔ Значения не печатать, не класть в аргументы, которые попадут в вывод.
- Создай в scratchpad два помощника и работай только через них:

```bash
# prom.sh <api-path> [--data-urlencode 'k=v' ...] — печатает только тело JSON
eval "$(grep -E '^export GRAFANA_PROM_(URL|LOGIN)=' ~/.zshrc)"
path="$1"; shift
curl -sS --max-time 60 -u "$GRAFANA_PROM_LOGIN" -G "$GRAFANA_PROM_URL$path" "$@"
```

```bash
# pq.sh '<promql>' [limit] — instant-запрос, строки «значение  метки», по убыванию
"$(dirname "$0")/prom.sh" /api/v1/query --data-urlencode "query=$1" | node -e '
const lim = Number(process.argv[1] || 60);
const j = JSON.parse(require("fs").readFileSync(0, "utf8"));
if (j.status !== "success") { console.log("ERROR", j.errorType, j.error); process.exit(1); }
const rows = j.data.result.map((r) => [Number(r.value[1]), Object.entries(r.metric).map(([k, v]) => `${k.replace(/^(ci_|turbo_task_|turbo_)/, "")}=${v}`).join(" ")]);
rows.sort((a, b) => b[0] - a[0]);
for (const [v, l] of rows.slice(0, lim)) console.log(`${(Math.round(v * 10) / 10).toString().padStart(12)}  ${l}`);
console.log(`(${rows.length} rows)`);' "${2:-60}"
```

- Запись (только для проб): `TELEMETRY_OTLP_ENDPOINT` и `TELEMETRY_OTLP_AUTH`, заголовок `Authorization: Bearer …`, путь `/v1/metrics`. Хост: `ssh -i ~/.ssh/mavauto root@77.222.38.47` — на нём же боевые сервисы и бенч-раннер: только чтение, если задача не в правке коллектора.

## Фаза 1 — Модель данных: как читать, чтобы не соврать

**Метрики** (имена после коллектора): `turbo_run_duration_ms_milliseconds_{bucket,sum,count}`, `turbo_run_tasks_{attempted,cached,failed}_total`, `turbo_task_duration_ms_sum_milliseconds_total` + `turbo_task_duration_ms_count_total` (у задач только сумма и счёт — перцентилей нет), `turbo_task_cache_events_total`. Метки: `ci_job`, `ci_event` (`pull_request`/`push`/`local`), `ci_runner`, `process_runtime_version`, `turbo_version`, `turbo_scm_branch`, `turbo_task_{name,package,cache_status,cache_source,exit_code,command}`, `turbo_run_exit_code`. `cache_status` строчными (`hit`/`miss`), `cache_source` заглавными (`LOCAL`/`REMOTE`).

⚠ **Счётчики накапливает коллектор** (`delta_to_cumulative`): пересоздание контейнера и простой потока дольше `max_stale` (72h) сбрасывают их в ноль. `increase()` сбросы переживает, но экстраполирует — счёт выходит дробным.

⚠ **Серии PR до 2026-09-28 10:53 UTC одноточечные.** Тогда `turbo_scm_branch` нёс ref PR (`N/merge`), у каждого PR были свои серии в 1–2 точки, и `increase()`/`rate()` по ним возвращают ПУСТО — без ошибки. Для этого периода бери сумму по сериям `max_over_time(<counter>[<окно>])` (коллектор копил с нуля). С отметки коллектор сводит ref к `pr`, прочие ветки кроме `master` — к `branch`, и `increase()` работает.

⚠ **Пустой ответ — ещё не «данных нет».** Сначала проверь, что запрос вообще может что-то вернуть на этом наборе серий (контроль: тот же запрос по `ci_event="push"`).

## Фаза 2 — Инвентаризация (всегда первой)

1. Имена метрик: `/api/v1/label/__name__/values` с `match[]={__name__=~"turbo.*"}`.
2. Значения меток (`/api/v1/label/<label>/values` с `match[]` и `start`): джобы, события, раннеры, версии Node и turbo, ветки.
3. Число серий и их источник: `count(max_over_time(<counter>[7d]))`, разбивка по `turbo_scm_branch`; квота Free — 10k активных.
4. Число прогонов по `ci_event`/`ci_job` — по `turbo_run_duration_ms_milliseconds_count`.

## Фаза 3 — Оси анализа

1. **Куда уходит время:** сумма длительностей по задаче / пакету / джобе, отдельно промахи и попадания.
2. **Самые долгие задачи:** средняя длительность промаха по `(package, task)`. Разброс одной задачи между пакетами — повод составить таблицу разделения по структурному признаку (инструмент сборки, симлинк, конфиг). Проверь КАЖДУЮ гипотезу по всем пакетам: верна та, что делит без исключений.
3. **Эффект контекста:** одна задача в разных джобах (одна против полного графа на 4 vCPU) — конкуренция или регрессия.
4. **Критический путь:** длительность прогона против самых долгих задач джобы. Задача короче пола джобы не окупит ускорения.
5. **Кеш:** доля попаданий по событию / джобе / задаче; `REMOTE` против `LOCAL`. Задача, которая на push промахивается без изменения входов, — кандидат в нестабильный ключ (сверь хеши `turbo run … --dry=json`).
6. **Падения:** `turbo_task_exit_code!="0"`, `turbo_run_exit_code`.
7. **Дрейф тулчейна:** `process_runtime_version` и `turbo_version` по раннерам и во времени; локальный против CI.
8. **Во времени:** `query_range` с шагом 1d по ключевым задачам; ступенька → `git log` за этот интервал.
9. **Качество телеметрии:** серии, которые плодят метки; пустые ответы стандартных функций; зонды, оставшиеся в данных (`ci_job` вида `*-probe`).

## Фаза 4 — Причину подтверждай пробой

- ⚑ **Находка из телеметрии — корреляция.** Причиной её делает локальный замер: тот же шаг, чередующиеся прогоны, контрольная рука. Пример 28.09: `bundle` пакетов с симлинком `shared/` в CI 24–58 с против 3,6–7,2 с; локально 12,5 с против 1,2 с; `DEBUG=rolldown-plugin-dts:*` показал отдельную TS-программу на каждый модуль `shared/`.
- ⚠ **Правдоподобную гипотезу опровергай данными.** Там же гипотеза «`types` в tsconfig» выглядела не хуже и разваливалась на двух пакетах в каждую сторону.
- ⚠ **Упавший эксперимент — не замер.** Сборка, умершая на `publint`, ничего не говорит о dts. Читай код выхода и последние строки лога.
- **Правка коллектора:** сперва локально — тот же образ по digest, экспортёр `debug`, синтетический OTLP и контроль без правки. Потом хост: загрузить `.new`, `validate` образом с `--env-file .env`, бэкап, подмена, `docker compose up -d --force-recreate`, сверка sha256 с репо. В конце сквозной зонд через публичный адрес с отдельным `ci_job` (`telemetry-*-probe`).

## Самокоррекция скила (ОБЯЗАТЕЛЬНО, в конце КАЖДОГО прогона)

Этот файл — живой; каждый прогон обязан его затачивать. После отчёта вынеси короткую секцию **«Самокоррекция»** — критику не своей работы, а САМОГО ЭТОГО СКИЛА: где его текст промолчал, соврал, был двусмыслен или избыточен — и это стоило времени, лишнего шага или риска ошибки.

1. **Привязка к ИНЦИДЕНТУ, не общие советы.** Каждая правка — из конкретного момента ЭТОГО прогона: «скил сказал X / промолчал про X → реальность Y → я потерял/чуть не ошибся на Z». Нет инцидента — нет правки (не выдумывай улучшения впрок).
2. **Высокая планка: изменило бы исход?** Предлагай, только если правка реально предотвратила бы ошибку, сократила перебор или сняла двусмысленность, на которой ты споткнулся. Косметику и «было бы неплохо» — отбрасывай.
3. **Разовое ≠ паттерн.** Специфику конкретного прогона (разовую) → в память, НЕ в скил. В скил идёт только повторяющийся класс, полезный СЛЕДУЮЩЕМУ ДРУГОМУ прогону.
4. **Сначала заточи, потом дописывай (анти-раздувание).** Предпочитай усиление существующего абзаца новой секции; если правка делает прежний текст избыточным — консолидируй, не дублируй.
5. **Предлагай, не применяй молча.** Выведи кандидатов таблицей (раздел | инцидент | предлагаемый текст), спроси разрешения. Применил по согласию → `.claude/commands/` это infra, в master напрямую, без changeset.
6. **Честность про «нечего править».** Прогон прошёл чисто и скил нигде не подвёл → так и скажи: «правок нет». Пустая самокоррекция честнее придуманной — пункты 1–2 это допускают.
