Актуализируй ОДНУ статью вики (`real-router.wiki`) против кода: разбери страницу на проверяемые утверждения, верифицируй КАЖДОЕ против первоисточника (`src` + тесты; при неоднозначности — измерь пробой, не рассуждением), найди чего код приобрёл за окно дрейфа и страница про это молчит, поправь симметрично во ВСЕХ сайтах утверждения. Прозу не переписывает, код не правит, без «go» не коммитит.

Входные данные:
$ARGUMENTS

Формат аргументов:

- **Имя страницы** — `navigate`, `navigate.md`, `guards`, `React-Integration`, `browser-plugin`. Регистр как у файла в `/Users/olegivanov/WebstormProjects/real-router.wiki/`. **Одна статья за прогон** — это не батч (батч doc-issue → `/doc-batch`).
- Опционально **фокус** после имени:
  - тема/раздел — `guards signal`, `navigate reentrancy` (сузить проверку до темы, обратный проход — по ней же);
  - issue/PR — `leave #1687 #1697` (актуализировать под конкретные изменения; окно дрейфа берётся из них, а не из даты страницы).
  - Без фокуса — вся страница.

Скилл — **аудит с правкой**, а не подтягивание сигнатур. Планка задана историей самого wiki-репо: правка чинит **модель читателя**, а не текст. Страница, где каждое слово формально верно, но которая молчит о том, что после отмены роутер вообще перестаёт спрашивать гварды, врёт читателю сильнее устаревшего типа. Отсюда три несущих требования, и они же — критерий приёмки прогона: (1) утверждение проверено против ИСХОДНИКА, а не против другой доки; (2) при неоднозначности — **измерено**, а не выведено; (3) правка легла во ВСЕ сайты, где это утверждение перечислено.

## Шаг 0 — Ориентация: тип страницы, первоисточник, окно дрейфа

**0.1 Страница существует?** `ls` в wiki-репо. Нет — НЕ создавай молча: выведи близкие имена (`rg -il '<имя>'`), спроси. Переименование (страница есть в `_Sidebar.md`, файла нет) — тоже находка.

**0.2 Тип страницы → первоисточник.** 82 из 128 страниц несут жёсткую схему `## 1. Overview … ## 8. Behavior`; остальные — гайды и концепты.

| Тип | Как узнать | Первоисточник (в порядке доверия) |
| --- | --- | --- |
| **Метод роутера** (`navigate.md`, `buildPath.md`, `addRoute.md`) | имя файла = имя метода, схема `## 1. Overview` | `packages/core/src/namespaces/<X>Namespace/**`, `src/api/`, `src/pipeline/`, `src/types/**` → тесты `packages/core/tests/functional/**` → `packages/core/INVARIANTS.md` |
| **Плагин** (`browser-plugin.md`, `hash-plugin.md`) | имя файла = имя пакета | `packages/<pkg>/src/**` → `packages/<pkg>/tests/functional/**` → `packages/<pkg>/INVARIANTS.md` |
| **Адаптер / компонент / хук** (`React-Integration.md`, `Link.md`, `useRoute.md`) | `*-Integration.md`, `use*.md`, имя компонента | `packages/<fw>/src/**` + **`shared/dom-utils/**` (симлинк — правда одна на 5 адаптеров, у `angular` git-копия)** → тесты адаптера |
| **Концепт / гайд** (`guards.md`, `navigation-lifecycle.md`, `error-codes.md`, `ssr.md`, `Testing.md`, `plugin-architecture.md`) | нет сайта 1:1 | пересечение: `core/src` + КАЖДЫЙ пакет, реализующий тему. **Здесь дрейф самый частый и самый скрытый** — у страницы нет одного «своего» файла, поэтому её никто не правит вместе с кодом |

**0.3 Окно дрейфа — приоритет чтения, а не граница.**

```bash
git -C ../real-router.wiki log -1 --format='%ad %h %s' --date=short -- <page>.md   # когда страницу трогали
git log --since=<эта дата> --oneline -- <пути первоисточника>                      # что уехало под ней
```

⚠ **Ходи между репо через `git -C <repo>` и абсолютные пути, НЕ через `cd`.** Рабочая директория Bash переживает вызов: один `cd` в вики — и следующая команда по путям main-репо молча падает `No such file`, что читается как «файла нет» вместо «я не там».

Плюс `packages/<pkg>/CHANGELOG.md` — записи новее даты страницы: это человеческий текст «что изменилось», с номерами issue/PR, и он часто прямо называет то, о чём страница молчит. Страница могла врать и ДО окна (утверждение бывает неверным с рождения) — окно говорит лишь, что читать первым.

**0.4 Состояние дерева вики.** `git -C ../real-router.wiki status --short` — там регулярно лежит ЧУЖАЯ незакоммиченная работа. Зафиксируй её список СЕЙЧАС, до правок: в конце он понадобится, чтобы не смести чужое в свой коммит.

## Шаг 1 — Инвентарь: что на странице вообще проверяемо

Разбери страницу на **атомарные утверждения**. Проверяемое = то, что код может опровергнуть.

- сигнатуры, перегрузки, формы вызова, типы аргументов и возврата;
- имена опций, их значения и **дефолты**;
- поля состояния/контекста, что из них заморожено и что writable;
- коды ошибок, **тексты сообщений**, бросается синхронно vs реджектит промис;
- порядок событий: кто кого ждёт, что синхронно, что в микротаске;
- **гарантии** — «никогда», «всегда», «идентично независимо от…», «единственный». Самое ценное и самое ломкое: гарантия ломается тихо;
- **перечисления и счётчики** — «all 16 codes», «four doors», «три места». Счётчик устаревает молча, а список рядом с ним — почти всегда неполон (прецедент: перечисление жило на трёх страницах и все три врали одинаково);
- **примеры кода** — каждый идентификатор, опция и поле в них — утверждение существования;
- **плагин-гейтед поведение** — страница описывает то, что даёт только плагин, как будто это делает bare core (или наоборот);
- ссылки на другие страницы.

Не утверждение и **не трогаем**: мотивация, аналогии, «зачем это нужно», порядок абзацев, стиль.

**Механический скан (дёшево, детерминированно — сделай до чтения):**

```bash
rg -o '\b(router|api|lifecycle|claim)\.[a-zA-Z]+' <page>.md | sort -u        # вызовы → должны существовать в src
rg -n '\b(all|both|each of the|the) (three|four|five|six|\d+)\b' <page>.md   # счётчики → пересчитать по коду
```

Ссылки — **node-сканом, не однострочным `rg`**: вики держит три формы (`](./Page)`, `](Page)`, `](Page#anchor)`) плюс `blob/master/...` на файлы main-репо, и rg по одной форме даёт спокойный пустой вывод вместо находки (проверено: узкий паттерн промолчал о 13 битых ссылках, среди которых `glossary.md → ./subscribeLeave` ×4 — страницы с таким именем нет, метод живёт в `leave.md`).

```bash
node -e '
const fs=require("fs"),path=require("path"),ROOT="/Users/olegivanov/WebstormProjects/real-router";
const pages=new Set(fs.readdirSync(".").filter(f=>f.endsWith(".md")).map(f=>f.slice(0,-3)));
for(const f of process.argv.slice(1)){const t=fs.readFileSync(f,"utf8");
 for(const m of t.matchAll(/\]\((\.\/)?([A-Za-z0-9][A-Za-z0-9._-]*)(#[^)]*)?\)/g))
  if(!/\.md$|^https?/.test(m[2])&&!pages.has(m[2]))console.log(`${f}: broken -> ${m[2]}`);
 for(const m of t.matchAll(/blob\/master\/([^)#\s]+)/g))
  if(!fs.existsSync(path.join(ROOT,m[1])))console.log(`${f}: blob gone -> ${m[1]}`);}
' <page>.md
```

Большая страница (>600 строк: `Angular-Integration`, `Svelte-Integration`, `Streaming-SSR`) — работай секциями и отчитывайся по секциям; не пытайся удержать её целиком.

## Шаг 2 — Верификация: три уровня доказательства

Для каждого утверждения — уровень, которого оно требует. Ниже уровня опускаться нельзя, выше — не нужно.

1. **Существование** — символ / опция / поле / export есть в `src`. Грепом, с цитатой строки.
2. **Пин** — поведенческое утверждение подтверждено ТЕСТОМ, который упадёт при его нарушении. Найди этот тест и назови его. Если утверждение не пинится ничем — это **самостоятельная находка**: контракт живёт только в доке, и его сломают, не заметив (→ предложи `[test]`-issue, не пиши тест сам).
3. **Измерение** — когда чтение неоднозначно: сколько раз что вызывается, в каком порядке, что видит листенер, аборчен ли сигнал, попадает ли ветка вообще. Напиши одноразовую пробу и **измерь**. Планка из истории репо: «Measured: `navigate()` invokes a route's decoder zero times». Утверждение «недостижимо / не вызывается / всегда» без измерения — не проверено.

   **Рабочий рецепт пробы** (три грабли, каждая стоит прогона): проба — временный `*.test.ts` в `packages/<pkg>/tests/functional/`, импорты **относительные** (`../../src/...`), удалить в конце.

   ```bash
   npx vitest run --root packages/<pkg> tests/functional/<probe>.test.ts --coverage.enabled=false
   ```

   - `--coverage.enabled=false` обязателен: порог 100 % валит прогон одиночного файла, и вывод тонет в отчёте покрытия;
   - **`console.log` из теста не показывается** — пиши результат `appendFileSync`'ом в файл в scratchpad и прочитай его после прогона;
   - репортёра `basic` в Vitest 4 нет — `--reporter=basic` падает `Failed to load custom Reporter`; просто не задавай репортёр.

**Гочи верификации:**

- **Первоисточник — `src` и тесты. НЕ пакетные `.md`.** `CLAUDE.md` / `ARCHITECTURE.md` / `README.md` / `INVARIANTS.md` дрейфуют ровно так же и часто являются ИСТОЧНИКОМ ошибки на странице (её оттуда и переписали). Они дают гипотезу и след — подтверждает код.
- **Пустой grep ≠ отсутствие.** `grep` здесь — шелл-функция поверх ugrep с `--ignore-files`; она молча пропускает игнорируемое и симлинки. Отрицательный вывод («этого в коде нет») перепроверяй вторым инструментом (`rg`, node-скан по `fs.readdir`) — и только тогда пиши «нет».
- **Код ошибки сверяй по ЗНАЧЕНИЮ константы, а не по её имени — они намеренно разные.** `constants.ts` держит `ROUTER_DISPOSED: "DISPOSED"`, а страница печатает то, что увидит пользователь (`RouterError(DISPOSED)`). Сверив с именем, «поправишь» верное в неверное.
- **Проба через `@real-router/*` может мерить СТАРЫЙ код.** Стухший `dist` шэдоуит name-импорты, относительный импорт идёт в `src`. Импортируй относительно — или `rm -rf packages/*/dist && pnpm install` перед тем, как поверить прогону.
- **Плагин-гейт.** Значительная часть валидаций и проверок в bare core отсутствует и включается `@real-router/validation-plugin` (и подобными). Проба без плагина покажет «не бросает» — и это не опровержение страницы, а уточнение: «под плагином». Проверь ОБА режима, прежде чем объявить утверждение ложным.
- **Каналы path/query.** Страница, не тронутая после разделения `state.params` (path) и `state.search` (query), кладёт query-ключ в `params` и мис-слотит третий аргумент. Ключ решается по `path` роута в том же сниппете; нет `path` — по смыслу ключа (`id`/`slug` → path; `tab`/`page`/`sort`/`q` → query).
- **Верифицируй против ТЕКУЩЕГО кода, а не против issue.** Issue/RFC, на который ссылается фокус, — гипотеза на момент заведения: цитируемая строка могла уехать, а поверх могло лечь ещё три изменения.

## Шаг 3 — Обратный проход: чего страница НЕ говорит

Самый ценный проход, и его пропускают чаще всего. Страница может не содержать ни одной ошибки и всё равно быть устаревшей: код приобрёл поведение, о котором она молчит, — а читатель уходит с неполной моделью и обнаруживает остаток на проде.

Где искать (в порядке отдачи):

- **CHANGELOG пакета за окно** — записи прямо описывают новое поведение и его радиус;
- **закрытые issue/PR за окно**, задевшие первоисточник — номера из `git log`, детали `gh pr view <N>`;
- **дифф поверхности**: exports, опции, коды ошибок, поля типов, что есть в `src` и не упомянуто ни разу на странице;
- **новые тесты** в тестовой директории темы — тест есть описанное поведение; describe-блок, которому нет соответствия в тексте, — кандидат;
- **тексты сообщений об ошибках** в коде: страница цитирует их дословно, и они меняются.

Итог прохода — явный список «страница молчит про X» с источником. Пустой список тоже валиден, но он должен быть **выведен**, а не пропущен.

## Шаг 4 — Симметрия: сиблинги в вики и зеркала в main-репо

Один факт живёт в нескольких местах, и ошибка копируется вместе с ним.

- **По вики:** грепни ВСЮ вики ключевыми токенами исправляемого утверждения (`rg -n 'decodeParams|REENTRANT_NAVIGATION' *.md`). Каждый найденный сайт проверь **отдельно** — не по аналогии: соседняя страница формулирует то же иначе и ломается иначе. Все сайты вики — твой скоуп, правь их в этом же прогоне.
- **По main-репо:** тот же факт зеркалится в **тексте сообщения об ошибке**, JSDoc (обычно двух), `CLAUDE.md`, `ARCHITECTURE.md`, `INVARIANTS.md` пакета, `README.md`, примерах. Зеркала **докладывай, не правь молча** — это другой репо и другой маршрут (pure-doc → напрямую в `master`, см. `/doc-batch`). Предложи их одним списком и жди «go». Разрешили — **scope коммита бери из commitlint-enum**, он закрыт: правка комментария в пакете → `docs(<pkg>)`, файл в `.claude/commands/` → `docs(config)` (`claude` невалиден; конвенция видна в `git log -- .claude/commands/`). Changeset на comment-only правку в `packages/*/src/` не нужен — `changeset-check.yml` висит на `on: pull_request`, прямой коммит в `master` его не запускает.
- Если правку сознательно НЕ ставишь в найденный сайт — напиши почему (там утверждение верно в своём контексте). Молчаливый пропуск запрещён: он и есть тот самый механизм, по которому три страницы врали одинаково.

## Шаг 5 — Правка

- **Минимальность по умолчанию:** правится утверждение, не абзац. Абзац переписывается, только если неверна модель целиком.
- **Схема и голос страницы сохраняются.** Нумерация разделов, порядок, терминология — как есть. Новый раздел добавляй, только если факту негде жить (прецедент: `### A cancelled navigation stops calling guards` под секцией про сигнал).
- **Называй остаточную форму.** Если после правки остаётся исключение или один непокрытый случай — напиши его прямо, а не оставляй читателю открывать самому.
- **Номер issue/PR в скобках** рядом с исправленным утверждением (`(#1713)`) — конвенция страниц.
- **Table-cell гигиена:** строка Markdown-таблицы — ОДНА строка; экранируй литеральный `|`, никаких сырых переводов строки. После правки глазом сверь, что столбцы целы.
- **Правишь ЗАГОЛОВОК — сперва грепни якорные ссылки на него** (`rg '\]\(\.?/?<page>#' *.md`): заголовок несёт якорь, и правка сигнатуры внутри него (`### 1. cloneRouter(router, deps?)`) тихо ломает каждую ссылку, которая на этот якорь целится.
- **Пример кода правится целиком**, а не по идентификатору: поправив сигнатуру, перечитай весь сниппет — обычно рядом мис-слотится аргумент и врёт комментарий в нём.
- Не добавляй «Last updated», не переставляй разделы, не трогай `_Sidebar.md` / `_Footer.md` / `Home.md` — кроме случая, когда страница реально отсутствует или переименована.

## Шаг 6 — Ревью, коммит

- **Прочитай полный `git -C ../real-router.wiki diff` сам**, до отчёта: доки требуют точности, а разъехавшаяся таблица и обрубленный сниппет видны только в диффе.
- **Коммит в стиле репо:** заголовок — само утверждение, не «update docs»; при двух — через «and»; в скобках номера issue. Тело: что страница говорила, почему это неверно, что измерено, и какие сайты затронуты. Образец: `docs: a cancelled navigation stops calling guards, and still delivers the leave (#1687 #1697)`.
- **`git add <файлы перечислением>`. НИКОГДА `-A` / `commit -a`** — см. 0.4, в дереве чужая работа.
- ⚠ **Провал коммита НЕ откатывает `git add`.** Хук `commit-msg` (commitlint) отбивает сообщение уже ПОСЛЕ индексации, и файл остаётся в индексе: следующий `git add <другое> && git commit` уносит оба под сообщением, описывающим только второе. Поэтому после ЛЮБОГО неуспешного коммита — `git status --short` ПЕРЕД следующим `add`, и `git show --stat` ПОСЛЕ коммита. Уже случилось → `git reset --soft HEAD~1` + `git restore --staged .` и пересобрать по одному (безопасно, пока не запушено).
- **Коммит — по «go». Push — по отдельной явной просьбе.**
- Wiki-коммит **не закрывает** issue main-репо (другой репо): в сообщении `Refs #N`, а `gh issue close #N` — вручную ПОСЛЕ push.

## Гейты

- **Без явного «go» — не коммитить и не пушить.** Правки остаются в рабочем дереве.
- **Не править `packages/*/src`.** Код-зазор (страница права, код баг; или контракт не пинится тестом) → находка в отчёт + предложение `/create-issue`. Даже однострочный.
- **Не переписывать прозу и не реструктурировать страницу.**
- **Не писать «проверено», если проверено рассуждением.** В отчёте у каждого вердикта — цитата кода/теста или число из пробы.
- **Не раздувать скоуп молча.** Нашёл дрейф на соседних страницах вне темы — доложи и предложи отдельный прогон, не тащи в этот.
- **«Дрейфа нет» — валидный исход.** Страница актуальна → так и скажи, с перечнем проверенного. Синтетическая правка ради правки хуже, чем ничего.

## Итоговый отчёт

1. **Таблица утверждений:** утверждение → строка страницы → первоисточник (файл:строка / тест / проба) → вердикт (**ВЕРНО** / **УСТАРЕЛО** / **ВРЁТ** / **НЕ ПИНИТСЯ** / **НЕПРОВЕРЯЕМО**) → что сделано.
2. **Измерено пробой** — что именно и с каким числом.
3. **Страница молчала про** — результат Шага 3.
4. **Симметрия** — сайты в вики (исправлены) и зеркала в main-репо (доложены, с предложенным маршрутом).
5. **Код-зазоры** → предложенные issue (заголовок + суть).

## Самокоррекция скила (ОБЯЗАТЕЛЬНО, в конце КАЖДОГО прогона)

Этот файл живой; каждый прогон обязан его затачивать. После отчёта — короткая секция **«Самокоррекция»**: критика не своей работы, а САМОГО ЭТОГО СКИЛА — где его текст промолчал, соврал, был двусмыслен или избыточен, и это стоило времени, шага или риска ошибки.

1. **Привязка к ИНЦИДЕНТУ, не общие советы.** «Скил сказал X / промолчал про X → реальность Y → я потерял/чуть не ошибся на Z». Нет инцидента — нет правки. Особые кандидаты: первоисточник искался не там; проба измерила старый код или не тот режим (плагин-гейт); утверждение объявлено ложным по чтению, а измерение показало обратное; найденный сиблинг пропущен.
2. **Высокая планка: изменило бы исход?** Косметику отбрасывай.
3. **Граница «как править конкретный вид доки» ↔ «этот скил».** Механика конкретного формата — не сюда. Сюда — процедура: где первоисточник, чем доказывать, где сиблинги, куда маршрутизировать.
4. **Сначала заточи существующий абзац, потом дописывай новый** (анти-раздувание).
5. **Предлагай, не применяй молча** — таблицей (раздел | инцидент | предлагаемый текст), спроси разрешения. Применил по согласию → `.claude/commands/` это infra: напрямую в `master`, без changeset.
6. **Честность про «нечего править»** — прогон прошёл чисто, так и скажи.
