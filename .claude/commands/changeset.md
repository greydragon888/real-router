Сгенерируй changeset файл на основе текущих изменений в git.

## Шаги

1. **Получи контекст задачи из GitHub issue:**

   ```bash
   # Извлеки номер issue из имени ветки (формат: <number>-<slug>)
   git branch --show-current | grep -oE '^[0-9]+'
   # Получи описание задачи
   gh issue view <number>
   ```

   **Если issue не найден — ПРЕКРАТИ выполнение** и сообщи об этом.

   ⚠ **Имя ветки — НЕ источник истины для номера issue, и ошибка тут молчаливая.**
   Ветка PR-группы называется по ПЕРВОЙ задаче группы (`/bugfix-batch`, серия
   независимых коммитов одного PR), поэтому номер из ветки может относиться к
   задаче, которая уже закоммичена, а changeset ты пишешь для следующей. Приоритет
   источников: **(1)** номер, переданный аргументом; **(2)** `#NNNN` из свежего
   диффа — нового теста, комментария фикса, сообщения последнего коммита;
   **(3)** имя ветки — последним, и только сверив `gh issue view <N>` с тем, что
   реально в диффе. Ошибка не всплывает нигде: changeset соберётся, гейт
   пропустит, а в release notes уйдёт ссылка на чужую задачу.

2. **Проанализируй изменения.** Changeset часто генерится ДО коммита фикса (например из `/bugfix` Фазы 4, или когда ветка задачи ещё указывает на тот же HEAD, что и `master`) — тогда `git diff master...HEAD` покажет **пусто** и слепое следование ему даст ложное «changeset не нужен». Сначала проверь рабочее дерево, и анализируй именно его, если оно грязное:

   ```bash
   git status --short          # есть ли uncommitted-изменения?
   git diff HEAD --stat        # working tree vs HEAD (включая ещё не закоммиченный фикс)
   git diff HEAD
   ```

   Если рабочее дерево чистое (фикс уже в ветке) — используй сравнение с базой:

   ```bash
   git diff master...HEAD --stat
   git diff master...HEAD
   ```

3. **Определи затронутые публичные пакеты по полю `private` в их `package.json`, а не по статическому списку** — список пакетов дрейфует (адаптеры `vue`/`solid`/`svelte`/`preact`/`angular`, новые плагины), и хардкод устаревает:
   - Для каждого затронутого пакета: `node -p "require('./packages/<pkg>/package.json').private || 'PUBLIC'"`. `PUBLIC` → changeset нужен. Приватных пакетов в `packages/` нет.
   - Код движка, FSM, эмиттера и логгера живёт в `@real-router/core` (`src/engine`, `src/utils/*`): правка там — changeset на `@real-router/core`.
   - Правка `shared/<dir>/*.ts` попадает в пакеты, которые линкуют каталог как `src/<alias>` (`CLAUDE.md` § Symlink Consumers): changeset — каждому из них, чьё поведение изменилось; `changeset-check.yml` требует его и на такую правку.

4. **Определи тип изменения** (следуй таблице bump в [.changeset/README.md](../../.changeset/README.md); pre-1.0: breaking → `minor`):
   - `major` — breaking changes
   - `minor` — новая функциональность
   - `patch` — исправления, рефакторинг
   - **Багфикс, ужесточающий публичный контракт** (тип / валидация / сигнатура), из-за которого ранее компилировавшийся или проходивший код консьюмера теперь падает — это `minor`, **не** `patch`: «fix» по намерению, но breaking по surface (сужение публичного контракта). «Bug fix → patch» из таблицы — только для фиксов, не меняющих публичную поверхность.
   - **Runtime-смена наблюдаемого поведения** в изменении, которое НЕ чинит дефект, без изменения сигнатуры (перф-рефактор, меняющий побочные эффекты / порядок событий / edge-case семантику — напр. event-delegation, где `stopPropagation` теперь блокирует навигацию, или detached-узел перестаёт навигировать) — тоже `minor`, **не** `patch`: ранее работавший рантайм консьюмера ведёт себя иначе → breaking, даже если это «perf fix» по намерению и типы не тронуты. Фикс задачи с меткой `bug` — `patch`, даже если меняет тайминг или порядок событий (поведение меняет любой фикс; так решил владелец): `minor` для него — только новый `throw`/reject или сужение контракта.

5. **Задавай вопросы ТОЛЬКО если** из issue и кода неоднозначно понятно, что реализовано (например, исправление стороннего бага).

## Формат changeset файла

```markdown
---
"@real-router/core": minor
---

Краткое описание изменений на английском языке (#NN).

- Детали изменения 1
- Детали изменения 2
```

## Правила

- Описание на **английском**, безличный тон ("Add feature", не "I added")
- Путь: `.changeset/<random-name>.md` (например `happy-dolphins-swim.md`)
- Один пакет на файл и ссылка `#NN` на PR/issue — `.changeset/check-changeset.mjs` отвергает changeset без них
- Если изменения только в CI/config/tests, в комментариях или JSDoc, или в доках внутри `src/` — changeset не нужен
- Для major — укажи как мигрировать
- Утверждение о поведении ДРУГОГО пакета или issue («как в #N», «включая `<Link download>`») проверь по коду или по закрывающему комментарию issue, а не по заголовку: скоуп issue меняется уже после того, как заголовок написан.

## Пример

```markdown
---
"@real-router/core": minor
---

Add support for async route guards (#NN)

- New `beforeEnter` and `beforeLeave` async guards
- Guards can return `false` to cancel navigation
```

## Самокоррекция скила (журнал кандидатов)

Скил правится по накопленному, а не после каждого прогона: правка по одному инциденту описывает случай, а не класс, а платит за неё каждый следующий прогон.

1. **Запись в журнал, а не правка** — после генерации changeset-файла. Где текст скила промолчал, был двусмыслен или неверен и это стоило вызовов, реплики владельца или риска ошибки, допиши строку в `.claude/skill-candidates/changeset.md` основного чекаута (gitignored; из worktree — `dirname "$(git rev-parse --path-format=absolute --git-common-dir)"`): дата, задача, раздел, класс (молчит / двусмыслен / неверен), инцидент, цена. Строка того же класса уже есть — допиши инцидент к ней. В отчёте — одна строка: что записано.
2. **Правка созревает, когда класс повторился** — в другой задаче или сессии. Неверный факт текста (команда, флаг, путь, число) — исправление, а не правило: его предлагай сразу. Планка: правка предотвратила бы ошибку или сняла бы лишние шаги.
3. **Разовое ≠ паттерн.** Специфику конкретного диффа/пакета (разовую) → в память, НЕ в скил. В скил идёт только повторяющийся класс, полезный СЛЕДУЮЩЕМУ ДРУГОМУ changeset.
4. **Правка не растит файл:** сначала заточи существующий абзац; новое правило называет, что в том же разделе сжато или удалено. Рост — только с согласия владельца.
5. **Предлагай, не применяй молча.** Созревшие правки — таблицей (раздел | инциденты из журнала | текст | что сжато), спроси разрешения; итог помечай в журнале. В скил — правило в настоящем времени, без номеров прогонов и дат; инциденты — в сообщение коммита. Применил по согласию → `.claude/commands/` это infra, в master напрямую, без changeset.
6. **Ничего не записано и не созрело** — так и скажи одной строкой.
