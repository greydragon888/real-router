Найди и исправь ошибки ESLint в указанном файле.

Входные данные:
$ARGUMENTS

Формат аргументов:

- Абсолютный или относительный путь к файлу

Шаги:

1. Прочитай файл
2. Проверь файл линтером. Предпочтительно ESLint MCP Server (`mcp__eslint__lint-files`); если он не экспонирован в сессии — БЕЗ попытки прямого вызова (она упадёт InputValidationError) перейди на CLI-фолбэк `pnpm exec eslint <путь>` (задокументирован в `.claude/mcp-guide.md`)
3. Проанализируй каждую ошибку и предупреждение
4. Исправь ошибки, соблюдая правила ESLint проекта
5. Повторно запусти тот же линтер для проверки исправлений

Важно:

- Линтер опционален по транспорту: MCP, если доступен, иначе CLI. Источник правды по ошибкам — exit-code CLI; IDE-диагностики (`<new-diagnostics>`) могут давать сдвинутые строки/колонки — опирайся на якоря по содержимому, а не на их номера строк
- Путь к файлу должен быть абсолютным при вызове MCP

Пример:

```
/esfix packages/core/src/Router.ts
```

## Самокоррекция скила (в конце каждого прогона)

Этот файл — живой. После фикса и финальной чистой перепроверки линтером вынеси короткую секцию **«Самокоррекция»** — критику не своей работы, а САМОГО ЭТОГО СКИЛА: где его текст промолчал, соврал, был двусмыслен или избыточен — и это стоило времени, лишнего шага или риска ошибки.

1. **Привязка к ИНЦИДЕНТУ, не общие советы.** Каждая правка — из конкретного момента ЭТОГО прогона: «скил сказал X / промолчал про X → реальность Y → я потерял/чуть не ошибся на Z». Нет инцидента — нет правки (не выдумывай улучшения впрок). Инцидент — довод в таблице кандидатов и в сообщении коммита; в текст скила идёт правило в настоящем времени с причиной в общем виде — без номера прогона, раунда и даты.
2. **Высокая планка: изменило бы исход?** Предлагай, только если правка реально предотвратила бы ошибку, сократила перебор или сняла двусмысленность, на которой ты споткнулся. Косметику и «было бы неплохо» — отбрасывай.
3. **Разовое ≠ паттерн.** Специфику конкретного файла/правила (разовую) → в память, НЕ в скил. В скил идёт только повторяющийся класс, полезный СЛЕДУЮЩЕМУ фиксу ДРУГОГО файла.
4. **Сначала заточи, потом дописывай (анти-раздувание).** Предпочитай усиление существующего абзаца новой секции; если правка делает прежний текст избыточным — консолидируй, не дублируй. Удаление устаревшего текста предлагай наравне с добавлением.
5. **Предлагай, не применяй молча.** Выведи кандидатов таблицей (раздел | инцидент | предлагаемый текст), спроси разрешения. Применил по согласию → `.claude/commands/` это infra, в master напрямую, без changeset.
6. **Честность про «нечего править».** Прогон прошёл чисто и скил нигде не подвёл → так и скажи: «правок нет». Пустая самокоррекция честнее придуманной — пункты 1–2 это допускают.
