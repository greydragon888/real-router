Найди и исправь ошибки ESLint в указанном файле.

Входные данные:
$ARGUMENTS

Формат аргументов:

- Абсолютный или относительный путь к файлу

Шаги:

1. Прочитай файл
2. Проверь файл линтером. Предпочтительно ESLint MCP Server (`mcp__eslint__lint-files`); если он не экспонирован в сессии — БЕЗ попытки прямого вызова (она упадёт InputValidationError) перейди на CLI-фолбэк `pnpm exec eslint <путь>` (задокументирован в `.claude/mcp-guide.md`)
3. Проанализируй каждую ошибку и предупреждение
4. Исправь ошибки, соблюдая правила ESLint проекта
5. Повторно запусти тот же линтер для проверки исправлений

Важно:

- Линтер опционален по транспорту: MCP, если доступен, иначе CLI. Источник правды по ошибкам — exit-code CLI; IDE-диагностики (`<new-diagnostics>`) могут давать сдвинутые строки/колонки — опирайся на якоря по содержимому, а не на их номера строк
- Путь к файлу должен быть абсолютным при вызове MCP

Пример:

```
/esfix packages/core/src/Router.ts
```

## Самокоррекция скила (журнал кандидатов)

Скил правится по накопленному, а не после каждого прогона: правка по одному инциденту описывает случай, а не класс, а платит за неё каждый следующий прогон.

1. **Запись в журнал, а не правка** — после фикса и финальной чистой перепроверки линтером. Где текст скила промолчал, был двусмыслен или неверен и это стоило вызовов, реплики владельца или риска ошибки, допиши строку в `.claude/skill-candidates/esfix.md` основного чекаута (gitignored; из worktree — `dirname "$(git rev-parse --path-format=absolute --git-common-dir)"`): дата, задача, раздел, класс (молчит / двусмыслен / неверен), инцидент, цена. Строка того же класса уже есть — допиши инцидент к ней. В отчёте — одна строка: что записано.
2. **Правка созревает, когда класс повторился** — в другой задаче или сессии. Неверный факт текста (команда, флаг, путь, число) — исправление, а не правило: его предлагай сразу. Планка: правка предотвратила бы ошибку или сняла бы лишние шаги.
3. **Разовое ≠ паттерн.** Специфику конкретного файла/правила (разовую) → в память, НЕ в скил. В скил идёт только повторяющийся класс, полезный СЛЕДУЮЩЕМУ фиксу ДРУГОГО файла.
4. **Правка не растит файл:** сначала заточи существующий абзац; новое правило называет, что в том же разделе сжато или удалено. Рост — только с согласия владельца.
5. **Предлагай, не применяй молча.** Созревшие правки — таблицей (раздел | инциденты из журнала | текст | что сжато), спроси разрешения; итог помечай в журнале. В скил — правило в настоящем времени, без номеров прогонов и дат; инциденты — в сообщение коммита. Применил по согласию → `.claude/commands/` это infra, в master напрямую, без changeset.
6. **Ничего не записано и не созрело** — так и скажи одной строкой.
