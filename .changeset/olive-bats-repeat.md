`RouterError.routeName` names a route, or nothing (#1785)

The field was inverted. Three `navigateToDefault` refusals put an English sentence in it — `"defaultRoute not configured"`, `"defaultRoute resolved to empty"`, `"defaultRoute did not resolve to a route name"` — while the two calls that DID name a route, `navigate("ghost")` and `navigateToDefault({ defaultRoute: "ghost" })`, left it `undefined`. A consumer writing `if (error.code === "ROUTE_NOT_FOUND") retry(error.routeName)` was handed prose to navigate to, or nothing at all. `message` was the bare code at every one of them, so the informative half of these errors sat in the wrong field while the right field was empty.

The reason now lives in `message` with the repository's `[router.*]` prefix, and `routeName` carries the route or is absent. Nothing is lost in the move: `message` previously added nothing to `code`.

**The named arc gives up #1184's zero-allocation fast path, deliberately.** `navigate()` to an unknown route returned `CACHED_ROUTE_NOT_FOUND_REJECTION` — a module-level frozen singleton shared by every caller, which is structurally unable to carry any one of them a name. It now allocates, exactly as the sibling door in `navigateToState` already did for the same reason. #1184 is a `[core][test]` issue: it pinned the singletons so that losing them could not happen *silently*, and that pin is inverted here rather than deleted, so re-sharing the instance to win the allocation back reds a cell. The two classes that keep the fast path — `SAME_STATES` and `ROUTER_NOT_STARTED` — have no per-call name to carry, and `SAME_STATES` is the only one of the three on a user-rate path (re-clicking the active link), while arriving at this one means the application named a route it never registered. No gated benchmark covers the arc.

⚠ **Visible downstream:** two repeats of the same failed navigation now hand back two DISTINCT error objects where they previously handed back one. Nothing in the repository keys behaviour on that identity — `@real-router/sources`' dismissable-error source dismisses on `version`, never on the instance — but a consumer memoising on the error object (a `useMemo` dependency, a `WeakSet` of seen errors) re-computes on every repeat where it previously did not. The `sources` cell that asserted the old identity is inverted rather than dropped.

Leaving `PRE_SUPPRESSED` is not a hole in the fire-and-forget guarantee (#721): `#settle` attaches the handler to exactly the promises that are not in that set, so the guarantee is held by the checkpoint rather than by a constant's identity. An un-awaited `navigate()` to a missing route is pinned to leak nothing.

**A second defect surfaced while fixing the first, and is fixed with it.** `#1960` states that every `RouterError` reaching consumer code is frozen, and its channel table passed because the arc it sampled handed back the frozen *singleton*. Measured: every FRESH rejection built in `NavigationNamespace` — `navigateToState`'s `ROUTE_NOT_FOUND` and `WRONG_CHANNEL`, and all three `navigateToDefault` refusals — reached `.catch()` unfrozen, so a consumer could annotate an error core threw at them and rewrite it for every other consumer that sees it. All of them are frozen at the reject now, which is also what keeps the new allocation from costing what the singleton gave.

What holds the rule is a walk rather than a list: `tests/functional/route-not-found-naming-authority-1785.test.ts` reads every `new RouterError(errorCodes.ROUTE_NOT_FOUND, …)` in `src` and fails on a string literal in the slot, so a new producer that spells prose there reds without anyone remembering to add a row. A type cannot hold this half — prose is a `string` like a route name is — and only the walk can tell a literal from an expression, including one hidden behind a cast: `as const satisfies` already hid a literal from a sibling walk in this repository (#2091), so the predicate reads through casts and a synthetic-source cell holds that in both directions. It is deliberately blind to the other half: a producer that omits the field passes it by construction, which is right for a call that named no route and wrong for one that did, so the behavioural table over every producer in `navigation/navigate/error-context.test.ts` owns that side.
