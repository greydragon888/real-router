# shared/dom-utils — Stable Shared Sources

> DOM helpers инлайнятся во все framework-адаптеры. Код **зрелый**, API устоялся.

## Status: stable

Эти файлы — общий слой для 6 адаптеров (Preact, React, Solid, Vue, Svelte, Angular). Любое изменение здесь немедленно попадает в 6 публичных bundle'ов. Относиться как к low-level примитиву, а не к «просто утилитам».

## Правила работы

### 1. Отладка начинается в адаптере, а не здесь

Перед правкой `shared/dom-utils/*.ts` убедись, что:

- баг воспроизводится **минимум в 2 адаптерах** (иначе это adapter-specific проблема обёртки);
- есть падающий тест в функциональном наборе соответствующего адаптера.

Если баг живёт только в одном адаптере — правка идёт в адаптер, не сюда.

### 2. Оптимизаций «на глаз» не делать

Функции уже прошли итерации:

- `buildActiveClassName` — токен-дедупликация через `Set`, O(n+m);
- `applyLinkA11y` — defensive null-guard + `hasAttribute` (не `getAttribute`);
- `buildHref` — optional `buildUrl` + undefined-fallback на резолвящую дверь `buildNavigationState` (#2250; `buildPath` остаётся правой частью `??` — там, где реестр не держит роутер или маршрут неизвестен);
- `createRouteAnnouncer` — double `requestAnimationFrame` + Safari-ready буферизация через `pendingText`.

«Рефактор ради чистоты» здесь запрещён — микро-изменение ломает сразу 6 bundle'ов. Изменение кода требует: конкретный баг/юз-кейс, тест на него и проверку каждого адаптера-потребителя (полный граф прогоняет pre-push).

### 3. Валидация изменений

Минимальный чек-лист перед коммитом:

```bash
for p in react preact solid vue svelte angular; do pnpm -F "@real-router/$p" test -- --run; done  # все адаптеры-потребители, по пакету на команду
pnpm -F @real-router/react test:properties -- --run  # property-тесты buildActiveClassName/buildHref
pnpm -F @real-router/svelte test:properties -- --run # property-тесты (дублируют React, оба должны пройти)
```

### `createDirectionTracker` — статус публичного API

Экспортируется из корневой точки входа всех шести адаптеров вместе с типом `DirectionTracker` (#2587) — в отличие от остальных `dom-utils`-утилит, которые пользователь получает через `RouterProvider` / `provideRealRouter(options)` (scroll, view-transitions, announcer) или через компоненты и директивы (link-utils). Статус — **unstable**:

- Аргумент — живой `Router`, а не любой объект с `subscribeLeave` (#1924): утилита резолвит инстанс в реестре internals ядра, чтобы видеть жизненный цикл транзишна.
- Установка — до `usePlugin(browserPlugin)` (см. комментарий о listener-ordering в `direction-tracker.ts`).
- `popstate` на URL текущего состояния роутера флаг не взводит (#2740): так приходит возврат URL-плагина после отказанного Back/Forward, а за ним не следует ни одного события транзишна. URL строит `buildUrl` URL-плагина; без него — и если `buildUrl` бросает — флаг взводит каждый `popstate`. Держит `packages/react/tests/functional/dom-utils/direction-tracker-refused-traversal-2740.test.ts`.
- Чужая ошибка не завершает транзишн в полёте (#2779): об отказе, не начавшем транзишна (например, `SAME_STATES`), и об отчёте плагина ядро сообщает тем же `TRANSITION_ERROR` и может сделать это, пока идёт другой транзишн. Транзишн завершает только своя ошибка — она несёт `toState` с `context` его `TRANSITION_START`; без транзишна в полёте флаг тратит любая ошибка. Popstate, пришедший посреди транзишна, ждёт повтора, но чужая ошибка снимает это ожидание: ею может быть отказ этого самого popstate, который URL-плагин разбирает на месте, — и тогда флаг тратит конец транзишна. Держит `packages/react/tests/functional/dom-utils/direction-tracker-early-refusal-2779.test.ts`.

Поведение меряет `packages/react` как владелец `shared/dom-utils` (white-box — `tests/functional/dom-utils/direction-tracker.test.ts`); остальные адаптеры держат `src/dom-utils` вне своего покрытия (`vitest.config.unit.mts`). Экспорт через точку входа проверяет `tests/functional/createDirectionTracker.test.ts` каждого адаптера.
